### Changed — Golem's consent screen groups model servers by location and names what it asks about (#857)

The block Golem prints before it sends data to a model server is now a "model servers" section. Servers are grouped under "On this machine (allowed automatically)" and "Remote". Each shows its name and URL (non-ASCII characters in the URL shown escaped, so a URL cannot pass off blank-looking characters as spaces), a `used for` row in plain words (chat, summaries, code delegation, embeddings; `(fallback)` for a use reached only through fallback entries), and a `checks` row for metadata requests such as the model list. Each remote carries its own state: `needs your OK`, `allowed by -allow-destination`, `allowed earlier this session`, or `not allowed (needs -allow-destination)` where Golem cannot ask. The question names exactly the remotes a yes admits, for example `Send data to opencode (remote) during this session?`. After `/grants clear`, the next admission asks about every remote not covered by `-allow-destination`, including ones approved before the clear.

During `/model set`, and when the next goal re-admits servers after `/grants clear`, the section prints on the REPL's output, where the question is asked, instead of stderr. `/grants` shows the section with each remote's state (after a clear, `not allowed (cleared; the next goal asks again)`, plus a line saying access was cleared). `golem models` labels the uses row `in route`. Color follows `NO_COLOR`, `TERM=dumb` and whether the output is a terminal, per output stream; only `golem index` and the top-level flags also take `-no-color`.

If the section cannot be written, Golem refuses the servers it would have asked about instead of asking, and a question whose prompt cannot be printed (a tool approval included) is never answered from typed-ahead input. Otherwise, which servers are admitted and when Golem asks are unchanged, as are the non-interactive denial error and exit code and all machine output (JSON records, `golem models -json`).
