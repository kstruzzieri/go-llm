### Security — Exec output no longer carries credential-path files (#777)

`read_file` already refused credential paths, but a command could print the same files. Command output from `run_command`, `start_command` and the post-write verifier is now screened, and commands that name a credential file are refused.

#### Upgrade note

- Commands that name a credential file are refused before they are planned or approved, with `tool call blocked by interceptor invariants (credential_path)`: an argv word such as `.env`, `--env-file=.env`, `HEAD~2:.env`, `@.env` or `-f.env`, or the same text in an inline `sh -c` script. A git exclusion pathspec such as `':(exclude,glob)**/.env'` passed as its own argv word is allowed. A command that names a credential file only to leave it out is refused too (`grep -r --exclude=.env x .`, `rsync -a --exclude .env a/ b/`, `find . -name .env`, `sh -c 'echo .env >> .gitignore'`); use a git exclusion pathspec as its own argv word, or for other tools a pattern that does not spell the name (`--exclude=.e*`). A `dir` at or below `.git`, `.ssh`, `.gnupg`, `.aws` or `.kube` is refused (`protected_dir`).
- Values of 8 bytes or more from `.env`-style files are withheld from command output, ordinary ones included: with `HOST=localhost` and `NODE_ENV=development` in `.env`, `localhost` and `development` are replaced by `[withheld: credential-path content (credential_path)]` wherever a command prints them. Each line of 8 bytes or more of a credential file, URL userinfo and `extraheader` values from `.git/config`, and the userinfo of a `.git-credentials` line (any credential-file line that is itself a URL), are withheld the same way. Only the matched span is replaced, and the result carries a `credential screen:` note with the count.
- Patch output stops at the first credential-file section: from a `diff -` or `+++ ` line that names a credential path on, that stream shows one marker, which says to rerun with the file excluded. A line that names a credential path in a `:`-separated prefix (`grep -rn`, `git grep`, some error messages) is replaced whole.
- A line over 32 KiB ends that stream's output with a marker; such a line used to show its first 32 KiB. A background job's unterminated last line is held until it ends.
- Each spawn walks the workspace and reads its credential files first, within a 5-second budget added to the tool's timeout. When that read cannot be completed (a file over 256 KiB, a directory this process cannot read, the budget exhausted), the command still runs, and its result shows the exit code and a note naming the cause, with no output, until the cause is removed. On Linux the common trigger is a container's data directory inside the workspace owned by another uid. A workspace root that was replaced or cannot be opened means the command is not run. The walk lists every directory outside `.git`, `vendor`, `node_modules` and `.superpowers` and examines only directories, files at a credential path and entries the listing does not report as regular files, so its cost grows mainly with the number of directories (#789): on one Apple-silicon Mac a tree of 355,611 entries in about 36,000 directories takes 1.7 to 2.1 s (3.8 s before #789), 100,000 files at 50 per directory 0.25 s (0.5 s before), and a directory-heavy tree of 1,000,000 entries 10.2 s, which exhausts the default budget. A tree that large (a big build or data directory, a Python environment, nested worktrees) makes every command wait the whole budget and withholds its output; `-credential-screen-budget` (`5s` to `5m`, default `5s`) raises the budget and the tool timeout grows with it, but every command still waits for the read. A plain file replaced by a directory after its parent directory was listed is not descended. Screening time also grows with the number of keys and the size of the output. On platforms other than Linux and macOS, exec output is always withheld.
- Library consumers of `agent/tools` exec get the screen with no switch: `RunCommand`, `StartCommand` and the verifier screen their output, and `agent/interceptor`'s `DefaultInvariants` gains four rows and the `CredentialArgv` check kind (and exports `IsGitConfigPath`). The `run_command` and `start_command` descriptions gain one sentence, which says that commands naming a credential file, or using a credential directory or `.git` as `dir`, are refused and that those files' content is withheld from output; a consumer who pins prompts or hashes tool specifications sees the change.
- The benchmark harness `cmd/llm-bench` keeps the `run_command` and `start_command` descriptions its registered corpora were built with (the new sentence is omitted there), so registered trace hashes are unchanged; its census now records a refused background start as a blocked call.

Not covered: encoded or transformed output, values under 8 bytes or spanning a line break, the userinfo of a URL when it holds an unencoded space or tab, committed content printed where the output does not show its path, files under directories the walk does not descend (a submodule's `.git/modules/<name>/config` among them), credential files outside the workspace, copies read back through the file tools, and AgentFlow and MCP output. `docs/golem.md` lists the rest.
