### Fixed — concurrent llm-bench runs no longer lose the shared judge cache (#593)

Two `llm-bench` runs opening the same judge cache at once could fail its schema migration with `table judge_cache already exists`, `duplicate column name`, or `database is locked`, and the run that failed printed `judge cache disabled` and judged every case uncached. Every judged run uses `<user cache dir>/go-llm/judge-cache.db` unless `-judge-cache` says otherwise, so any two runs started together could hit this. Each migration step now claims its version row before its DDL, in the same transaction, and is skipped when another run already applied it. Cache connections retry lock contention from another run for up to five seconds before failing; this applies to cache reads and writes as well as to migrations. On Windows, a UNC or device path for `-judge-cache` is now rejected, as for go-llm's other SQLite stores, and the run continues uncached.
