## Approval decisions

1. `/context` reports the last assembled request, not a forecast of the next turn. Retain the five bucket totals already computed by assembly and capture pressure through the existing request-scoped `Turn.Observer` seam. Early exhaustion without a matching complete breakdown displays buckets as unavailable. No stream-json event is added.
2. `/model set` executes synchronously in the existing REPL loop. The next goal is read only after it finishes; it uses the new configuration on success and the old one on failure. If interactive destination consent is needed, `ReadAnswer` consumes the next input as that answer, just as existing prompts do; scripts without an interactive prompt require the existing exact destination allowlist. No background command queue or busy-input rejection is added.
3. **Model-state rollback and destination consent have different boundaries.** A failed model selection preserves the caller, options, budget, routing metadata, tools, conversation, and session identity. A destination grant explicitly approved while preparing that selection remains a session grant; real metadata/probe-cache observations also remain. The failure message says when a grant was retained. `/grants clear` revokes it normally.
4. Decision 3 is a deliberate qualification of the handoff's broad phrase “everything unchanged.” It is the smallest design that satisfies #376's explicit caller/options/budget rollback requirement while keeping one registry and router. If destination grants must also roll back, revise this design before implementing #376; do not silently substitute multiple provider stacks.
5. Roles select model chains while the interactive agent's routing use case stays `agent`. Accepted thinking controls carry forward and are re-gated; a chain entirely without thinking support clears those controls with a notice, matching startup behavior.

## #375 specification

### P1. Retain accounting and reuse the request observer

Add one additive field `agent.Pressure.Buckets` of concrete value type `PressureBuckets`: `Available bool` and integer `Pinned`, `ToolSchema`, `History`, `ToolOutput`, `Retrieval` totals. A value keeps Pressure comparable and snapshots independently copyable. Available distinguishes an actual zero estimate from a path that did not retain a breakdown. Tag this Go/observer-only field `json:"-"` to preserve existing raw Result JSON compatibility as well as the explicit trace/machine projections.

Refactor the existing dominant-cause calculation to return its totals and derive the cause from those same totals. Preserve message attribution precedence, tie ordering, guarded estimates, saturation, and mixed/legacy attribution semantics. Normal legacy and mixed assembly populate buckets from the exact output state used for InputTokens, including post-eviction/projection and final full-state exhaustion when accounting is valid. Do not add a second accounting walk for the same result. Arithmetic failure takes precedence over availability, including at the final full-state check.

Earlier exhaustion paths retain their existing scalar InputTokens, Cause, and Mitigation. Pinned-only, allocator-reservation, custom-compactor error, and arithmetic-failure results leave Buckets unavailable where no corresponding complete output accounting exists. Do not fabricate a full-state breakdown or change exhaustion semantics to make totals fit. Test the unavailable paths explicitly. Existing trace/telemetry projections remain unchanged; this work adds no machine-output event.

Add a private CLI `pressureCapture` implementing `agent.Observer` with three no-op base callbacks and `agent.PressureObserver`. It holds a mutex, latest event, and a seen boolean; its snapshot returns values under that mutex. Allocate one capture per attempted Runtime turn, and retain its run/thread identity from the IDs the CLI already supplies. No public recorder is needed.

- Compose it FIRST, ahead of the existing composed renderer/telemetry/feedback/grounding observer, using the existing fanout. The fanout stops on the first error; capture must therefore finish before any downstream observer can fail. Do not alter the order among existing observers or introduce a second forwarding implementation.
- Allocate/store it immediately before the Runtime call. A pre-assembly failure has no sample; a valid LevelOK does. Capture works without telemetry and when warning display is disabled.
- Retain the latest step, including normal after warning, exhaustion, and a sample followed by model/observer failure. Release the capture mutex before other observers run.
- Separate instances isolate concurrent named and stateless requests. Library hosts can compose their own recorder through Turn.Observer, which already satisfies #375's request-scoped runtime seam.
- No `golem.PressureState`, `Turn.Pressure`, reservation claim, reuse error, runtime cache, or Runtime implementation edit.

### P2. Read-only `/context`

`/context` accepts no arguments and performs no model, summarizer, registry, or database call. Add a help entry. `/git-context refresh` keeps its existing meaning.

The REPL keeps the capture for its latest attempted Runtime turn. On successful `/new`, `/clear`, or `/resume`, clear that pointer; failed session operations preserve it. With `--no-session`, retain the latest stateless turn's capture normally; a disabled session command does not pretend a session transition occurred.

Literal display contract, with trailing newlines:

| Case | Output |
|---|---|
| Arguments supplied | `usage: /context` |
| Missing runtime | `context: runtime unavailable` |
| No sample | `context: no pressure sample for the current session` followed by the configured-limits line |
| Sample header | `context: last assembled request run-1, step 1` |
| Sample classification | `pressure: warn; cause: history; mitigation: warn` |
| Sample estimate | `input estimate: 7680 / 10000 tokens (76.8%)` |
| Retained buckets example | `bucket estimates: pinned 1000; tool_schema 680; history 5000; tool_output 800; retrieval 200 tokens` |
| No retained breakdown | `bucket estimates: unavailable for this assembly` |
| Configured limits example | `configured input ceiling: 11024 tokens; explicit output reserve: 1024 tokens` |

The sample numbers are illustrative fixture values, not production constants. Render the retained `InputTokens`, `InputBudget`, and `UsedPct`, with a human step number of internal `Step + 1`. The configured-limits line describes current configuration; a zero explicit reserve is printed as zero and does not mean the provider reserves no output. The retained input budget is the authoritative denominator after normalization/reserve handling. Do not reconstruct it independently in the CLI.

All token usage is labelled an estimate. Level, cause, and mitigation describe that estimate; no provider-measured input usage is claimed. Display all five retained buckets in the fixed order above when Available; otherwise print the unavailable line. The fixture bucket sum is 7680. Pin internal Step 0 as step 1 in both /context and the renderer's `step 1/N` footer. #375 reads the unchanged startup budget for configured limits; #376 switches this read to Runtime.Budget().

### P3. Freshness and compaction

Always say “last assembled request.” That sample can predate automatic history compression, `/compact`, `/think`, or changed system/tools. Inspection does not rerun assembly and cannot predict a future goal.

Manual and automatic compaction leave the historical pressure sample intact. `/compact` continues to report its separate stored-history before/after estimates. The next turn gets a fresh capture and records the pressure of its actual assembled request. A successful `/model set` clears the CLI's old pressure pointer, so the new model starts with an explicit no-sample state.

## #376 specification

### M1. Command and selection rules

Support `/model` and `/model set <role|name>` only. Invalid forms print `usage: /model [set <role|name>]` and perform no provider I/O.

Resolve against the process's frozen, final effective config, including the startup-selected/discovered provider URLs. Expose the exact post-override `*Effective` already constructed by bootstrap as `Bundle.Effective`, alongside the compatible Config field. Candidate planning uses that value directly; do not re-Materialize Config or reuse main's earlier pre-discovery value. Effective's existing copy-on-write ownership applies: consumers must not mutate its shared configuration. This is not a config reload command.

1. An exact configured role takes precedence. Use `providerbootstrap.PlanRoleRoute` with use case `agent`; preserve the complete ordered fallback chain, including entries temporarily unavailable.
2. Otherwise, if the first slash-delimited segment is a configured provider key, preserve the entire nonempty suffix as the model ID and select that qualified singleton strict chain.
3. Otherwise treat the entire input as a bare model ID: qualify it when exactly one provider is configured; with multiple providers require `provider/model`. Do not scan names or inventories to infer a provider. Config Models keys are roles, not aliases. Empty IDs, invalid/cyclic/empty role chains, and failed model preflight produce explicit errors.

Canonicalize BEFORE passing candidates to shared parseSelector/selectorProvider helpers, both of which split at the first slash. For example `vllm/meta-llama/Llama-3.3-70B-Instruct` retains its complete suffix when vllm is configured; bare `meta-llama/Llama-3.3-70B-Instruct` becomes that same canonical selector in a vllm-only config and is ambiguous in a multi-provider config. An unrecognized prefix is part of a bare ID, not an unknown-provider syntax exception. LookupAny is not a discovery mechanism: it only sees startup-refreshed providers. No new parser grammar or optional name scan.

Build one `PlannedRoute` and derive `chainPlanFor` from it. Feed that same value to network planning, preflight, caller construction, ceiling resolution, and status. Do not use availability-filtering `config.Resolve` to reconstruct a role's fallback chain. A role named `coding` still runs this interactive agent under use case `agent`.

The command is process-local and works with `--no-session`. It preserves conversation bytes, summary, session ID and provider session header, grants for tools/project context, mounted tools, memory, checkpoints, and background jobs. `/new`, `/clear`, and `/resume` do not reset the selected model.

### M2. One registry/router and explicit additive consent

Reuse the existing `providerbootstrap.Bundle`. Retain the pure effective config/planning inputs required by the handler; do not construct another registry, router, provider stack, or duplicate registry implementation.

Before candidate metadata/probe I/O:

- Build candidate route edges through `BuildNetworkPlan`, including model-refresh, capability-probe when enabled, slot-probe where applicable, and parent-following dispatch. Union them with the session's stored manifest edges, including after revocation when those edges remain known but unauthorized. Validate the complete proposal before any admission publication. Existing provider URLs are frozen; the original `-base-url` remains attached to its original provider.
- Render the proposed manifest through the existing destination-consent surface. Local destinations and exact existing grants/flags retain their normal treatment. Prompt only when the proposal reaches an uncovered remote destination; use the existing `ReadAnswer`/interrupt discipline.
- Use exactly one consent decision and one gate publication for the complete proposal: Extend when admitted, or the existing ensure/Install consent path applied to that full proposal when revoked. Do not first re-admit the old manifest and then ask separately about the candidate. Denial, cancellation observed at the final pre-publication check, malformed manifest, and failed publication leave the live gate and model configuration unchanged. Recheck context after the consent reader returns and immediately before publication. Publication determines consent success; cancellation arriving afterward does not undo an installed grant. No new-destination request may precede admission.
- After admission succeeds, explicitly approved grants remain for the process session even if subsequent model validation fails. The displayed grant manifest records them and `/grants clear` revokes them.
- Superset extension also retains grants for routes switched away from. Document that `/grants` shows session authority, including inactive routes; switching models is not revocation. Use `/grants clear` to revoke. No per-route grant marker or pruning mechanism is added.
- If prior grants were revoked, do not reuse the old `granted` field. The consent baseline is only the existing exact allow flags and normal loopback policy. A remote destination re-approved after revocation counts as newly approved relative to that baseline, even if it appeared in an older session grant.

The private CLI admission wrapper `extend(ctx context.Context, edges []provider.DestinationEdge) (newGrantAdmitted bool, err error)` returns true only after successful publication when at least one remote destination in the complete proposal was not covered by the prior live granted policy (or by the flags-only baseline after revocation). Return false when the complete proposal needs no new/renewed remote permission: existing grants, local destinations, exact flag coverage (including a flag unused by the startup manifest), and purpose-only additions do not alone count. A local model candidate can still produce true after `/grants clear` if the retained manifest requires renewed remote consent. Denial, cancellation before publication, invalid proposals, and failed CAS return false with an error. Compute this outcome under the admission mutex; no persistent grant-tracking field or new result type is needed. The model handler retains this boolean through later validation/publication steps and uses it only if those steps fail.

Add `DestinationGate.Extend(policy, manifest) error` for an already installed gate:

- The supplied manifest must be a complete superset of the current edges with every existing purpose/provider destination unchanged; reject removals and retargeting.
- Validate the manifest and exact policy before publication. Failed validation leaves the current state untouched.
- Give admitted snapshots a private revocation token allocated as a fresh non-zero-size object (one byte suffices). Do not use `new(struct{})`, a shared sentinel, or an externally supplied token. Each Install/Narrow mints its own fresh token; Extend can retain only the token from the current snapshot of that same gate. Bind records that token in the capability. Previously bound capabilities remain valid because their exact edges are preserved.
- `Install` and `Narrow` mint fresh tokens; `Clear` removes the installed snapshot. Preserve their existing revoke-all and failed-Install behavior. Foreign-gate capabilities remain invalid.
- Publish extension using compare-and-swap against the snapshot it validated. A concurrent Clear, Install, Narrow, or competing Extend wins; report an error without resurrecting or overwriting that state. Do not retry using stale consent.
- Transport authorization loads the current snapshot once and requires a non-nil capability, current snapshot, and capability token, then matching token identity and the existing exact provider/destination checks. Token ownership is private and unique to a gate's revocation generation, so no additional capability.gate pointer is needed. Gate and atomic state must not be copied after use. Foreign-gate rejection is a required behavioral test, including two gates with identical manifests/policies before and after repeated extensions; missing/zero-token capabilities must also fail closed.

Keep admission read, consent, publication, and bookkeeping under destinationAdmission's existing mutex, as ensure already does. After successful gate publication, update its manifest, copied edges, granted policy, and admitted flag together; failure leaves that bookkeeping unchanged. Revoke cannot interleave between publication and bookkeeping. This is the only new authorization primitive; no candidate scope, allow-all, retry loop, or cross-gate transaction.

### M3. Keep slot governance correct for newly selected providers

At bootstrap, construct the existing lazy slot source over all configured `slot_discovery` providers, with the same guarded clients, overrides, and probe binder. Continue refreshing inventory only for `ActiveProviders` at startup.

Constructing a source and reading cached capacity make no network requests. Inactive providers must stay silent until admitted and used; every later probe remains guarded by the destination gate. Unknown capacity retains the existing conservative single-slot behavior. This avoids a second admission counter or mutable provider-activation subsystem.

Use this construction consistently for all consumers of the bootstrap helper. Update its tests/comments to distinguish “configured for lazy governance” from “active for startup I/O.” An inactive-provider fixture must prove zero HTTP requests while its configured governance remains discoverable through the existing capacity seam.

### M4. Prepare, then publish one runtime snapshot

Add a concrete `golem.Configuration` value containing only application `System`, extra `Tools`, `ModelOptions`, `Orchestrator`, and `Budget`. These are the execution inputs that must change together for library hosts such as Firn.

Add `Runtime.ReplaceConfiguration(ctx context.Context, cfg Configuration) error` and the minimal `Runtime.Budget() agent.Budget` value getter. No Configuration getter, public ModelSelection, or Options selection field. Keep requested selector, canonical chain, use case, strictness, and input-ceiling source in private CLI `sess.selection`, initialized at startup and replaced after successful publication. `Tools` means extra tools, as in Options and Replace, not the runtime-owned file-tool prefix. Budget reads the current snapshot under the existing lock, with the same after-Close access convention as ModelOptions().

Extend `turnSnapshot` to own these fields. Preserve the existing `Replace(system, tools, ...ModelOptions)` API; it preserves the added fields at publication, including after tool validation races with another replacement. `ModelOptions()` retains its existing copy and after-Close semantics.

Preparation sequence:

1. Validate command/selector and construct planned route and candidate manifest.
2. Complete the explicit admission operation in M2 using an interruptible child context.
3. Use existing model registry lookup and `preflightToolCapable`, honoring `-no-cap-probe` and its normal cache/probing rules. Do not add a test chat or warm-up request.
4. Read accepted current runtime options. Add a small inverse of thinkModelOptions that maps accepted ModelOptions to the resolver input: nil/no effort -> empty default, explicit false -> off, explicit true without effort -> on, accepted effort -> low/medium/high. Match formatThinkOptions precedence (false before effort); do not parse its display string. Re-run resolveThinkOptions for the candidate chain using that value, not the stale startup flag. Copy only the resolved Think/ThinkEffort back into the candidate, preserving unrelated options. For an all-ThinkNone chain, clear thinking controls and print the existing explanatory notice after a successful switch; mixed/unknown handling and per-fallback suppression stay unchanged.
5. Call `resolveInputCeiling` with the candidate chain/use case and original explicit ceiling/output-reserve settings. Retain its explicit-override, chain-minimum, eligibility, quality ceiling, default-output reserve, and safe-fallback semantics. Missing context metadata produces the existing labelled safe fallback, not an invented hard failure.
6. Build the new caller and orchestrator through the existing factory, preserving progressive context, verifier/late-verifier, canary/interceptors, and tool invocation limits. Rebuild parent-following dispatch as described in M5.
7. Validate the complete candidate, recheck cancellation, and call `ReplaceConfiguration` once. No provider I/O, Tool.Spec call, or user callback occurs under the Runtime lock.
8. After successful publication, perform infallible CLI bookkeeping in the synchronous handler before the next prompt: replace sess.selection (with an owned chain copy), sess.tools, sess.orch, and sess.newOrchestrator with the prepared values; reset last-routed display and pressure capture; then report status. Allocate/validate all candidate values before publication. Failed publication changes none of these fields. Thinking preflight reads sess.selection.chain rather than a second thinkChain cache.

`ReplaceConfiguration` mirrors New/Replace's tool validation and ErrClosed precedence and rejects a nil replacement orchestrator. Check context at entry and again under the publication lock after validation; cancellation while Tool.Spec is running must not install a candidate. Failure installs nothing. It copies options/tool slices; callers must not concurrently mutate supplied inputs. A complete replacement explicitly replaces the whole tuple; it is not a field merge.

Reservation remains the linearization point. Runs already reserved retain old system/tools/options/orchestrator/budget for all their steps. Later reservations see the complete new tuple. Preserve runtime-owned workspace tools and ScopeGuard. Borrowed orchestrators/providers remain caller-owned; replacing them does not close resources still in use.

Move every run-budget read to the snapshot. Pass `snap.budget` explicitly from Run through `saveThread` to `compressConversation`. In `CompactThread`, capture `snap := r.snap` under `r.mu` in the same critical section that reserves the thread, and pass that captured budget into compression. The compression helper must not reread Runtime budget/configuration after reservation. Keep the configured summarizer route/provider unchanged. The new model can cause existing history to need compaction on its next turn; switching itself neither calls the summarizer nor rewrites history.

Status, `/context` configured limits, and CLI trace-budget metadata read Runtime.Budget(); thinking display reads ModelOptions(), and /think gating reads sess.selection.chain. The CLI's synchronous command loop owns publication and bookkeeping, so no second configuration publisher can interleave those display reads. Library run consistency comes from reservation of the entire snapshot, not from CLI display fields. Remove sess.thinkChain and all REPL reads/writes that treat sess.budget as current. If non-REPL AgentFlow/planning consumers still need that budget field, name it startupBudget and keep it immutable; startup-only modes retain their behavior because /model is REPL-only. Rebinding sess.orch/newOrchestrator nevertheless prevents later callers or rebuilds from reviving the startup caller. Do not substitute a mutable swappable caller: an old reserved turn must keep its original caller/options/budget tuple.
