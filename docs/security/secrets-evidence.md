### Background job handles (a separate workflow effect)

A background job's handle is `bg-` plus 32 hex digits from 16 random bytes (`agent/tools/background_manager.go`, `readHandle`), and the `start_command`, `command_status`, `command_tail` and `command_stop` results print it on its own line. The payment-card rule reads a maximal run of 13 to 19 digits. In a handle each hex digit is a decimal digit with probability 10/16, independently, and a run of uniform digits passes Luhn with probability 1/10. An exact sum over the 32 positions (a dynamic program over run lengths, in rational arithmetic) gives the probability that a handle holds a Luhn-valid run of 13 to 19 digits:

p = 0.1758% per handle, about 1 in 569 jobs (computed exactly from the 10/16 and 1/10 probabilities above, not sampled).

The rule also exempts repeated digits and the 7 published test numbers, which lowers p by less than one part in ten billion, so p is a tight upper bound. Under a default-on Secrets every result that prints such a handle is replaced, whatever the job's output: the job runs, but the model never sees its handle or its output. The census redraws these handles, and any handle flagged by a detector, so that its rates stay a function of the file. This effect is not in the `command_tail` rates above and adds to them.

## What this report does not claim

- No live credentials; generated fixtures minimize committed secret-shaped material; GitHub enforcement is verified separately.
- No model-recovery claim: whether a model recovers after a block is not measured. Bounded, paired live runs on the affected workflows are the first task of an eventual post-#518 flip PR (spec §5.6).
- The case table is a stratified probe set, not a population. Its rates are per cell, and no headline recall is claimed.
- The tool-args carrier always puts the value in a single JSON string field named `content`. Key-aware argument scanning (`ScanAssignment` on JSON keys, nested objects) is outside the measurement.
- The census covers only the strata listed above. It classes only `adversarial-fixture` files (BC5), so a benign file whose role is deliberate secret-shaped test data counts toward the false-block rate, except where it sits under the BC5 adversarial-fixture paths.
- Summary generation calls the provider outside the hooks and is not protected; canary minting is untouched (spec §5.5).
- #424 exact configured-secret matching and its outbound checks are not covered (spec §9).
