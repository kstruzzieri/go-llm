# Upgrading to go-llm v0.4.0

Read this before upgrading from v0.3.0. For older dependencies, apply the
[v0.3.0 upgrade notes](../../CHANGELOG.md#changed--v030-consumer-upgrade-notes-560)
as well. The [v0.4.0 changelog](../../CHANGELOG.md#040---2026-09-29) contains the
full entries.

## Breaking changes

### Go 1.27 minimum (#565)

Build consumers with Go 1.27 or newer. `go get` raises the consuming module's
`go` directive to at least `1.27.0`; update its CI and build images together.
The release toolchain is Go 1.27.1. Standalone go-llm binaries also adopt Go
1.27's GODEBUG defaults; see the changelog for the removed compatibility defaults.

### Session saves return the committed revision (#542)

`conversation.Store.Save`, `conversation.SQLiteStore.Save`, and
`golem.SessionStore.Save` now return `(int64, error)`. Assign the returned
revision only after success; do not increment the input revision locally:

```go
revision, err := store.Save(ctx, conv)
if err != nil {
    return err
}
conv.Revision = revision
```

Custom session stores must enforce atomic compare-and-swap (CAS), return zero
on error without changing storage, and prevent a deleted/recreated ID from
reusing a stale revision. Changing only the method signature is insufficient.
Revision zero means create; it does not predict the committed revision.

Opening a sessions database applies migration v5. Upgrade and restart all
writers sharing that database together and discard pre-upgrade snapshots.
v0.1/v0.2 upserts and v0.3 creates are refused after migration, including on a
fresh database; matching positive v0.3 CAS updates can still succeed. Revisions
erased before migration cannot be recovered. Delete remains unconditional.
See [conversation persistence](../library.md#conversation-persistence) for the
full custom-store, conflict, migration and exhaustion contracts.

### Canonical destination flags only (#501)

Replace `-allow-destination "provider=URL"` with the repeatable canonical form
in Golem, go-llm-mcp and callers of `provider.ParseDestinationFlag`:

```sh
-allow-destination "openai/https://api.openai.com"
```

Destination normalization and admission policy are unchanged.

### Exported struct literals and comparability

Use keyed literals when constructing `agent.Result`, `agent.ToolResult`,
`agent.InspectedMessage`, `consult.Consultant` and `consult.Evidence`: these
structs gained fields. `consult.Consultant` also contains a slice now, so it
can no longer be compared with `==`/`!=` or used as a map key. Compare the
fields relevant to the caller instead.

## Other consumer-visible changes

- Nested agent runs inherit parent input, generation and step limits (#449).
  An unset parent input ceiling resolves to 8,192. Finite total allowances
  reserve estimated prompt tokens plus a fixed generation cap before inference
  and cover concurrent and repeated children. Budget refusal can occur earlier;
  unknown or failed usage retains its reservation. This is admission accounting,
  not an exact billing guarantee. `Result.Usage` remains local;
  `Result.DescendantUsage` reports descendants separately. Golem still has no
  finite aggregate spend pool. `Orchestrator.Run` seals and cancels its run
  context on return; custom nested work must be joined before then to receive
  complete descendant usage.
- Opt-in interceptors include native child workspace refusals in the parent's
  risk report (#555). Findings are informational; they do not alter grants.
- Workspace writes, deletes and undo checks on Linux and Darwin use admitted
  directory descriptors (#552). Concurrent creation and unsupported no-replace
  operations are refused; conditional mutations require readable content. See
  [workspace mutation limits](../least-privilege.md) before relying on this as
  leaf/content CAS or on other platforms' checked-path behavior.
- Feedback, fingerprint and routing-feedback migration runners serialize
  concurrent opens (#549). Configure a positive `busy_timeout` on every
  migrating connection and finish journal-mode setup before racing openers.
  Use a DSN or connection hook, not a one-off PRAGMA; built-in hardened and
  routing-feedback openers now set the timeout in their DSNs. RAG migrations
  and the transcript legacy audit-column upgrade are outside this change.
- Background feedback collectors reject new registrations and explicit-time
  records after shutdown starts; `Close` drains admitted work (#569).
- Golem quotes terminal controls in streamed output and terminal-bound `-p`
  answers (#433). Redirected output remains byte-for-byte unchanged.
- Codex consultation is opt-in, pinned to native CLI 0.153.4 and requested model
  `gpt-6-astra`, and requires both process-egress and vendor-runtime consent
  (#546). Native host access remains trusted. Exec is the default;
  `transport: "app-server"` is explicit. Before downgrading, remove Codex
  declarations and new configuration keys (`transport`, `disabled_mcp_servers`,
  `trusted_vendor_runtime`) that the older strict parser cannot accept. See
  [consultation configuration](../consult.md).

## Consumer compatibility checked for this stamp

Targeted compile checks used Go 1.27.1 and release source `dd2ae2394548`, with
a temporary modfile replacing go-llm; consumer source and module files were
unchanged. These checks compile packages and tests without executing them or
building the complete applications.

| Consumer checkout | Result |
| --- | --- |
| Firn IDE `bca223f94a11` | Its current `be8e25924d08` go-llm pin compiles `internal/ai` and `internal/git`. The release source compiles `internal/git`, but `internal/ai` fails because `MemorySessionStore.Save` still returns only `error`. Migrate the store and its callers as described above before bumping the dependency. |
| Flux ML `cd6529235673` | No go-llm requirement or Go imports in the available checkout; no active integration to compile. |
| Quantum Trader `f2e399bbd5a2` | No go-llm requirement or Go imports in the available `backend/go` module; no active integration to compile. |

Firn's custom store currently performs unconditional in-memory upserts, so it
also needs CAS and protection against revision reuse. Its consuming `go`
directive must move from 1.25.0 to at least 1.27.0. No legacy
`-allow-destination` flags were found in these checkouts; external launch
scripts still need the canonical form. Consumers upgrading from Firn's older
pin must also account for the v0.3.0 changes linked above.

## Release scope

The [v0.4.0 milestone](https://github.com/kstruzzieri/go-llm/milestone/1) has
11 closed issues and no open issues at the release stamp: #433, #449, #501,
#542, #546, #549, #552, #555, #564, #565 and #569. All are present in the
release source; the ten changelog fragments cover the consumer changes,
while #564 is CI tooling. Quarantined ingestion (#434), retrieval tagging
(#435), the adversarial corpus (#452), and detector evaluation (#517) remain
in v0.5.0. The [least-privilege roadmap](../least-privilege.md) adds no scope
to this release.
