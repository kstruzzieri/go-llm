# Upgrading to go-llm v0.7.0

Read this before upgrading from v0.6.0. For older dependencies, apply the
[v0.6.0 upgrade guide](v0.6.0.md) first; it links the earlier notes in turn.
The v0.7.0 section of the [changelog](../../CHANGELOG.md) contains the full
entries.

v0.7.0 makes Golem's requests reusable from a provider's prompt cache and shows
what a session cost. Inside a goal, earlier tool results now reach the provider
with the same bytes on every request, compaction moves the cached prefix far
less often, `/context` prices usage from an optional per-model `price`, and
openai-compat clients send each host only the cache key it documents.

Most upgrades need no code change: no exported Go API changed incompatibly
(see [Consumer compatibility](#consumer-compatibility-checked-for-this-stamp)).
Check three things: move off AgentFlow 1.2.1, pass a cache-affinity option if
you point `openaicompat.NewClient` at an OpenCode mirror, and expect different
token counts from Abacus RouteLLM and from Ollama embeddings.

## Changed defaults and new requirements

### openai-compat sends each host only the cache key it documents (#749)

Before v0.7.0 every openai-compat client sent `x-opencode-session` to every
host. Each client now picks a mode from its base URL:

| Base URL | Mode | What is sent |
| --- | --- | --- |
| `https` on `api.openai.com` | `openai` | Body field `prompt_cache_key`, an HMAC of the session id |
| `https` on `openrouter.ai` | `openrouter` | Header `x-session-id`, the same HMAC |
| `https` on `opencode.ai` | `opencode` | Header `x-opencode-session`, the raw session id |
| Anything else: local llama.cpp, Abacus, any `http` URL | `none` | Nothing |

The HMAC uses a random per-process secret, so its value changes on restart and
is neither the thread id nor the workspace hash. A request with no session id
(`-no-session`, `golem -p`) sends nothing in any mode.

- Code that builds `openaicompat.NewClient` against an OpenCode mirror on
  another host, or over `http`, must now pass
  `openaicompat.WithCacheAffinity("opencode")` to keep the header OpenCode
  requires. In `models.json` the same setting is
  `"cache_affinity": "opencode"` on the provider; in `llm-bench` it is
  `-cache-affinity`.
- `cache_affinity` accepts `none`, `openai`, `openrouter` or `opencode`. Any
  other value, or the field on a provider that is not `openai-compat`, makes
  the config fail to load.
- Abacus stays `none`: on chat completions, 16 interleaved runs detected no
  statistically significant benefit from `prompt_cache_key`, and none was ruled
  out ([measurement](../llm/benchmarks/2026-11-01-abacus-cache-affinity.md)).

### Move off AgentFlow 1.2.1 (#756)

The AgentFlow floor stays at 1.2. AgentFlow 1.2.1 counts a changed file's latest
matching receipt from any attempt, so a stopped attempt's edit satisfies the
attempt that replaces it. On 1.2.1, `-agentflow-resume` would have run the gates
and completed the step on an edit nobody accepted. Use AgentFlow 1.2.2, which
Golem's compatibility CI now pins (#760), or 1.2.0.

On every `1.2.1` build (such as `1.2.1rc1` or `1.2.1+local`):

- `-agentflow-resume` refuses after its read-only checks and before its first
  change to the run, and asks AgentFlow for no recovery advice.
- `-agentflow-status` reports every state that would otherwise exit `2` as
  blocked and exits `3`. JSON mode keeps AgentFlow's bytes on stdout and prints
  the refusal as one `golem:` line on stderr.
- A `-review-manifest` run refuses before `init`.
- A complete run still reports its verified proof, and fresh `-plan` and `-goal`
  runs without a review manifest still run.

An AgentFlow 1.2 whose patch version cannot be read is refused for recovery the
same way.

### AgentFlow step loops stop earlier on a stalled step (#731)

Golem's serial step loop now asks AgentFlow `next-step --explain`.

- When AgentFlow reports remaining step work but no eligible step, the run stops
  before `finish-run` and names the reason code and AgentFlow's diagnostics.
- A same-plan `-review-manifest` round over a run that died with an attempt open
  now stops before it records the review, opens an amendment or calls the model.
- A reason code this Golem does not know, which a newer AgentFlow may add, stops
  the run until Golem is updated. Malformed explain replies stop the run too.

Scripts that match the old `next-action` stop text need updating. Exit codes,
resume dispositions and `-agentflow-status -json` are unchanged.

### Token counts read differently on two backends (#751, #753, #758, #759)

**Abacus RouteLLM (`routellm.abacus.ai`).** The client now reads Abacus's own
usage shape. Net behavior against v0.6.0:

| Response | Input and total | Cached and cache-write counts |
| --- | --- | --- |
| Non-streaming, any model | Exact: `raw_input_tokens` + `cache_read_input_tokens` + `cache_creation_input_tokens` | Both as sent; an absent read counter is a reported 0 |
| Streaming, served by `gpt-5-mini`, `gemini-3.5-flash`, `grok-4.3` or `deepseek-ai/DeepSeek-V4-Flash-0731` | Exact, recovered from Abacus's weighted count | Cached as sent; an absent counter is a reported 0; no write count |
| Streaming, any other served model, the first request included | `0` (unknown) | Cached as sent; an absent counter is a reported 0; no write count |

A `route-llm` request is looked up by the model that served it. Abacus sends no
exact input count on a stream and, on models that bill cache writes, counts the
written tokens at 1.25 without saying how many, so those requests cannot be
recovered ([measurement](../llm/benchmarks/2026-11-03-abacus-stream-weight.md)).

A `PromptTokens` of 0 means unknown, not free. Golem names such a request under
`excludes unreliable usage` and leaves it out of the dollar total. A run budget
charges that call's full reservation instead of treating it as cheap. Code that
divides by, sums or displays `PromptTokens` from an Abacus stream must handle 0.

**Ollama embeddings.** An embedding now reports the server's `prompt_eval_count`
as its input count. It used to report the number of input texts, so
`usage.prompt_tokens` on the compat `/v1/embeddings` endpoint changes for
Ollama-backed models. A server that omits the count reports 0.

### `models.json` entries that used to load can now be refused (#751)

Only configs that use the new `price` field are affected. A model's optional
`price` is in USD per 1,000,000 tokens:
`{"input": 3, "output": 15, "cached_input": 0.3, "cache_write": 3.75}`.

- `input` and `output` are required. An unknown member, such as a typo'd
  `input_per_mtok`, or a value that is not finite and at least 0, fails the load.
- Two entries that name the same `provider/model` and both set a price must
  carry the same one.
- `config.Document.SetRoleModel` and `ForkRoleModel` clear the price when the
  role, or the fork, moves to a different `provider/model`. `SetRoleModel`
  reports it as `SetRoleModelResult.DroppedPrice`.

There is no built-in price table. A model without a `price` is never guessed.

### Compaction and history compression behave differently (#745, #746, #748)

For Golem:

- A compacting step inside a goal now drops to 75% of the budget left for
  messages, and what it dropped stays out of every later request in that goal.
  The newest tool result is never dropped to reach that mark; when it cannot be
  reached without doing so, compaction falls back to the previous just-enough
  fit.
- History compression across turns counts only the user and assistant text it
  replays, still triggers at half the input ceiling, and evicts to half of that.
  The summarizer receives only that replayed text, not tool results. `golem
  compact` reports the same estimate, so tool-heavy threads show smaller numbers.
- The project and Git snapshot fence key now rotates when run text contains it,
  and later goals keep the new key. A rotation misses the cache for one request.

For library callers:

- `agent.ContextManager.CompactionLowWater` defaults to 0, which keeps the
  previous fit. Golem sets 0.75 through the new `golem.NewContextManager`.
- With a durable summary, the legacy compactor now drops prior-turn history
  before current-run tool results, as documented. It previously did the reverse.
  This applies at any `CompactionLowWater`.
- Tool results are framed under one key per result, reused on every later request
  of the run, instead of one fresh key per request. `Result.Events` can now
  carry the kinds `fence_rotation` and `fence_scan_limit`, so a switch over
  `Kind` should tolerate them.
- A custom `Compactor` is trusted: text it synthesizes while building a request
  is not scanned for live keys. It receives the fraction in
  `TokenBudget.LowWaterFraction` but no sticky eviction.
- `agent.Request.SystemKeys` names the fence keys `System` frames untrusted text
  under (12 or more characters of `A-Z` and `2-7`; anything else is refused before
  the first model call). A caller that sets none gets no system-prompt rotation.

### Library additions

All additive. An unkeyed literal of a struct that gained a field stops compiling;
`agent.Budget` keeps its positional shape.

- `provider.Usage`: `CachedPromptTokens`, `CachedPromptTokensReported`,
  `CacheWriteTokens`, `CacheWriteTokensReported`. `PromptTokens` still includes
  cached tokens, and a Reported flag tells a measured zero from an absent counter.
- `agent`: `Request.SystemKeys`, `Result.SystemKeys`,
  `ContextManager.CompactionLowWater`, `TokenBudget.LowWaterFraction`,
  `NewRouterSummarizerWithUsage`.
- `golem`: `NewContextManager`, `Turn.SystemKeys`.
- `conversation.CompressMessagesWithCost`.
- `config`: `ModelPrice`, `ModelConfig.Price`, `ProviderConfig.CacheAffinity`,
  `SetRoleModelResult.DroppedPrice`.
- `openaicompat`: `WithCacheAffinity`, `InferCacheAffinity`.
- `ollama`: `Client.EmbedWithPromptCount`, `EmbedResponse.PromptEvalCount`.
- `fingerprint/probers`: `WithOpenAICompatUsageObserver`,
  `ProberFactoryInput.UsageObserver`.
- `agentflow`: `Client.ExplainNextStep`, `Client.ProbeRecovery`,
  `ParseRecordedBlockers`, `RecordedBlockers`, `RecordedBlocker`,
  `NextStepExplanation`.

## Protections that are opt-in

v0.7.0 adds no opt-in protection and changes none: nothing under `mcp/`,
`mcpclient/`, `agent/tools/` or `agent/interceptor/` changed since v0.6.0. The
[v0.6.0 table](v0.6.0.md#protections-that-are-opt-in) still describes what a
default session does not get: the native command sandbox, exact configured-secret
protection and MCP HTTP authentication all stay opt-in.

The fence-key changes are on by default, not opt-in. Tool-result key rotation
runs in every `agent` run. System-prompt key rotation runs in Golem, and in a
library host only when it passes `Request.SystemKeys`.

## Measured cache reuse

`llm-bench -cache-probe` on one scripted session, share of turn-1 prompt tokens
served from cache
([local](../llm/benchmarks/2026-10-31-cache-probe-baseline.md)):

| Target | Model | Uncompacted | Under compaction pressure |
| --- | --- | ---: | ---: |
| llama.cpp, before this work | `qwen3-coder-next` | 1.3% | 2.7% |
| llama.cpp, this release | `qwen3-coder-next` | 78.4% | 52.3% |
| OpenCode Go | `kimi-k2.7-code` | 77.0% | 51.9% |
| CommandCode | `moonshotai/Kimi-K2.7-Code` | 77.3% | 51.3% |
| Abacus RouteLLM | `gpt-5-mini` | 76.9% | 49.6% |

Each hosted row is one run per scenario. They show the pattern holds on each
host; they do not measure whether a cache key helps, or what a real workload
saves.

## Other consumer-visible changes

- `/context` prints `usage (this process)`, `last run`, `est. cost` and one
  `side task <name>` line per side task that made a call. Totals are process-local.
  See [Calls, caching and cost](../golem.md#calls-caching-and-cost).
- Startup can print `notice: summarize uses the same model as chat
  (<provider/model>); set defaults.summarize to a cheaper model to lower
  compression cost`. Scripts that treat stderr lines as errors need updating.
- The end-of-run footer gains `(C cached)` when the backend reports the counter,
  and counts `compaction` and `fence rotation` events when there are any:
  `done · 4 steps · 9.2s · 18342 tok (12800 cached) · 1 compaction · 1 fence
  rotation`. On Abacus an unknown input reads `0 tok`.
- `-telemetry` step spans gain `cached`, `cached_reported`, `cache_write` and
  `cache_write_reported`; the run span gains `compactions` and `fence_rotations`,
  omitted when zero. The schema version stays 2.
- Human `-agentflow-status` lists each current recorded blocker after the
  diagnostics. The lines are display-only.
- `llm-bench` gains `-cache-probe`, `-cache-probe-scenario`, `-cache-probe-out`
  and `-cache-affinity`, and a separate forged-close corpus
  (`docs/llm/traces/injection-forged-close/`). An injection cases file whose
  `source` is neither `injection` nor `forged-close` is now rejected.

## Consumer compatibility checked for this stamp

`apidiff -m` between `v0.6.0` and release source `00e0098f` reports no incompatible
change to any exported, non-internal package.

Targeted compile checks used Go 1.27.1 and the same source, with a temporary
modfile replacing go-llm in a scratch copy of Firn; consumer checkouts were
unchanged. Each check was repeated against `v0.6.0` so that failures could be
attributed. These checks compile packages and tests without executing them.

| Consumer checkout | Result |
| --- | --- |
| Firn IDE `7cbc703e` (develop) | Pins go-llm v0.5.0 with `go 1.27.0`. `go build ./...` (with a placeholder file in `frontend/dist`) and `go test -run '^$' ./...` pass on both `v0.6.0` and the release source. |
| Flux ML `cd6529235673` | No go-llm requirement in the available checkout; no active integration to compile. |
| Quantum Trader `048e8f9ee630` (develop) | No go-llm requirement in the available `backend/go` module; no active integration to compile. |

Firn's own `openaicompat.NewClient` clients infer their mode from the endpoint.
Firn hands a session id only to `opencode.ai` over `https`, which still gets
`x-opencode-session`, so its traffic does not change. The comment at
`internal/ai/runtime.go:376-377` saying go-llm sends the header for any non-empty
id goes stale at its next go-llm bump. Firn is still on v0.5.0, so it must apply
the v0.6.0 notes too.

## Known issues

New or narrowed in this release:

- **Abacus streamed usage.** Every served model outside the four named above reads
  as unknown on a stream, so most multi-step Golem runs on them are left out of
  the dollar total. The recovery rests on Abacus's measured weighting: if Abacus
  began streaming exact counts, go-llm would overcount by `cached - floor(cached *
  w)`, and its negative-count check would not catch that. A gateway in front of
  Abacus on another host does not match the host rule, so its counts pass through
  as sent. The legacy `GenerateStream` path also passes an Abacus count through
  unchanged; it was never measured and Golem does not use it. An absent
  `cache_creation_input_tokens` leaves the write count unreported rather than a
  reported 0; nothing reads that flag today.
- **Fence keys** (#745). A key the model echoes into tool-call arguments is
  disclosed to that tool while still live for the rest of that step; it rotates
  before any later request. The scan matches case, nested `\uXXXX` escapes,
  fullwidth ASCII and separators, but not other compatibility forms or
  cross-script look-alike letters. A scan that reaches its limit resets the live
  keys once, which misses the cache.
- **Compaction** (#748). Mixed assembly still upgrades and downgrades structured
  alternatives as free budget changes, which moves the prefix (3 of 7 requests in
  the characterization test). After a low-water compaction, a later step's
  `Pressure` counts only what that step dropped. If one turn's 4-exchange floor
  exceeds the 50% mark, history compression still runs every turn.
- **AgentFlow recovery** (#756). The guard reads the version AgentFlow prints, so a
  build containing the 1.2.1 change that still reports `1.2.0` is not caught.
  Also present on 1.2.0: AgentFlow's `verify_step` accepts an empty list of
  current-attempt file receipts, so a same-plan review round over a blocked
  attempt can complete the replacement attempt without it recording anything.
  1.2.2 alone does not close this.
- **`cache_affinity` in config panels** (#749). `config.ProviderSpec` and
  `configview` do not carry the field yet, so a panel cannot set or clear it, and
  a round trip off `openai-compat` and back drops a hand-set `"none"`.
- **Usage figures** (#751). A side-task call that fails is not counted, a rare
  concurrent identical embed can count twice, and Ollama embeddings still report
  `TotalTokens` 0.
- **Capability evidence** ([#734](https://github.com/kstruzzieri/go-llm/issues/734)
  to [#741](https://github.com/kstruzzieri/go-llm/issues/741), not in this
  release). Probe verdicts are keyed by provider name, so two configs that name
  different endpoints `local` share rows, and a hosted "yes" does not expire.

Unchanged from [v0.6.0](v0.6.0.md#known-issues), none fixed here:

- Sandboxed commands can write `.git` metadata
  ([#721](https://github.com/kstruzzieri/go-llm/issues/721)).
- launchd is reachable from Seatbelt commands
  ([#712](https://github.com/kstruzzieri/go-llm/issues/712)), and Seatbelt cannot
  load toolchains outside its reviewed roots
  ([#722](https://github.com/kstruzzieri/go-llm/issues/722)).
- Golem cannot authenticate to a token-protected `go-llm-mcp`, and the #424 and
  #428 residuals stand.
- Grants do not notice workspace changes
  ([#420](https://github.com/kstruzzieri/go-llm/issues/420)).
- Local stdio MCP servers keep host-user authority
  ([#580](https://github.com/kstruzzieri/go-llm/issues/580)).
- Seatbelt and Bubblewrap descriptor races
  ([#711](https://github.com/kstruzzieri/go-llm/issues/711),
  [#484](https://github.com/kstruzzieri/go-llm/issues/484)), the workflow route a
  `-review-manifest` round can replace
  ([#679](https://github.com/kstruzzieri/go-llm/issues/679)), and the containment
  inventory gaps ([#699](https://github.com/kstruzzieri/go-llm/issues/699)).

## Release scope

v0.7.0 ships the work landed since v0.6.0 and has no milestone scope of its own:
the 2026-10-30 prompt-caching plan (P0 #743, P1 #745 with #746, P2 #748 with #747,
P3 #749, P4 #751), the Abacus usage work (#753, #758, #759) and two AgentFlow
changes (#731 through PR #744, and #756). Docs, CI and test-only
changes are #750, #752, #754, #755, #757 and #760.

Provenance and approval continuity (#581 to #584), quarantined ingestion (#434),
retrieval tagging (#435), scoped retrieval for dispatch children (#554), #469 and
the second `golem ops` PR (#654) were outlined as v0.7.0 at the 2026-10-27 freeze.
None has landed. They move to the
[v0.8.0 milestone](https://github.com/kstruzzieri/go-llm/milestone/4).
