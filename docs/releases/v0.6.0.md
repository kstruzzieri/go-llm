# Upgrading to go-llm v0.6.0

Read this before upgrading from v0.5.0. For older dependencies, apply the
[v0.5.0 upgrade guide](v0.5.0.md) first; it links the earlier notes in turn.
The v0.6.0 section of the [changelog](../../CHANGELOG.md) contains the full
entries.

v0.6.0 changes what a Golem session may do by default: with no profile flag
and none of the legacy opt-in flags it can only read the workspace (#387). The
release's new protections are opt-in: the native command sandbox (#576, #708),
exact configured-secret protection available through `-interceptors` (#424)
and optional MCP HTTP authentication, under which TLS without a token stays
unauthenticated (#428). Golem also requires AgentFlow 1.2 or a later 1.x
(#705, #730).
Most upgrade work is operator-side (adding `-profile trusted` or an opt-in flag
to scripts, installing AgentFlow 1.2). Library breaks are concentrated in the
`golem` package (`Options.Tools`, `CommandPermissions`) and the SQLite
openers.

## Changed defaults and new requirements

### Golem starts in the read-only Inspect profile (#387)

A session started without `-profile` is Inspect: the model gets `list`,
`glob`, `search` and `read_file` and nothing else.

- A legacy opt-in flag still selects Trusted when `-profile` is omitted:
  `-allow-write`, `-allow-exec`, `-scratch`, `-allow-tool`, `-rag-db`,
  `-agent-memory` (with a session), `-delegate`, `-dispatch`, `-mcp-stdio`,
  `-mcp-http`, `-progressive`, `-grounding` or any `-sandbox`. Startup then
  prints `profile: trusted (selected by <flag>)`. `-profile inspect` with one
  of them is a usage error. AgentFlow modes stay Trusted.
- A session with none of those flags loses what v0.5.0 mounted by default:
  retrieval, auto-indexing, the embedding route and the `memory_search` tool.
  Add `-profile trusted` (and the flags you need) to scripts that relied on
  them. `/remember`, `/forget` and
  `/memories` still work, and existing indexes and memory databases are kept.
- In an Inspect session `/allow-write` and `/allow-exec` are refused; restart
  with `-profile trusted` and the flag.
- Interactive and one-shot sessions print a `permissions:` line on stderr.
  Result JSON and stream events keep their schemas.

Library callers:

- `golem.Options.Tools` requires `Profile: golem.ProfileTrusted`. The zero
  value is `ProfileInspect`, and `golem.New` rejects any caller tool under it,
  even one that only reads, with an error wrapping
  `golem.ErrProfileIncompatible`. This is a runtime failure, not a compile
  error. Admission also runs at `Replace` and `ReplaceConfiguration`, so a
  caller that adds tools later fails there too. Callers that never pass tools
  keep working as Inspect.
- Trusted puts an approval floor under extra tools: a non-library tool that
  mutates or uses the network always prompts, even if it declares
  `ApprovalNever`.
- `dispatch` is refused alongside a `ScopeGuard`, and an allowlist that
  admits `dispatch` must name all four reads and every child tool it carries.
- `golem.ProfilePreview` is reserved and always rejected.

### AgentFlow 1.2 or a later 1.x is required (#705, #730)

Golem refuses AgentFlow 1.1 and older before any other AgentFlow call
(`agentflow 1.1 is too old; need >= 1.2`), and still refuses 2.x. Upgrade
AgentFlow before or with Golem. CI's AgentFlow compatibility job pins the
v1.2.0 release commit.

AgentFlow 1.2's `next-action` answers only from the ledger rows it validated.
If the step, command or file receipt ledgers change while it runs, it reports
`state_invalid`. Golem already refuses that state: `-agentflow-status` exits 3
with `resume: blocked by invalid Agentflow state`, and `-agentflow-resume`
stops before any change. When you see that refusal while another process is
writing `.agent/`, run the command again. Golem does not use 1.2's
`next-step --explain` or the new `recorded_blockers` key yet.

From AgentFlow 1.1 (#705), a gate that timed out is resumable:
`-agentflow-status` offers the step (exit 2), and `-agentflow-resume` runs it
again in a new attempt. A workspace an earlier Golem left with a blocked
timed-out attempt, reported then as exit 3, is now resumable and costs a model
run for that step. A timed-out receipt inside a completed attempt (only
AgentFlow 1.0 recorded those), or one the step-run ledger records
inconsistently, still gets exit 3 and the archive remedy.

### AgentFlow runs fail closed on unfinished or unverified state (#642, #643, #651, #652, #688, #689)

Scripts that drive `-plan`, `-goal`, `-agentflow-status` or
`-agentflow-resume` see different exits:

- A fresh `-plan` or `-goal` refuses a workspace whose `.agent/` holds
  execution history (exit 1, naming the artifact) instead of relocking over
  it. Resume the run, or move `.agent/` aside.
- A step run that fails (provider or observer error, exhausted context,
  interrupt, failed gate, unreceipted edit) records its attempt as `blocked`.
  `-agentflow-status` then reports `step_unclaimed` (exit 2), and
  `-agentflow-resume` runs the model again in a new attempt rather than
  settling the old one on its gates. A script that resumes on exit 2 now pays
  for a model run. An attempt left open after its gate failed is blocked by
  resume and re-run the same way.
- A fresh `-plan` and `-agentflow-resume` exit 1 without running
  `finish-run` or building a proof while AgentFlow reports step or attempt
  work.
- Status and resume verify an existing proof first; an invalid one stops
  status (exit 3) and resume (exit 1) before any recovery mutation.

Edits from a failed attempt stay in the workspace: restore or delete them
before resuming, or the new attempt must write each still-changed in-scope
file again.

### SQLite 3.51.3 and stricter store opening (#632, #648)

- go-llm links modernc.org/sqlite v1.46.2 (SQLite 3.51.3, the WAL-reset
  corruption fix). A module that requires `modernc.org/libc` directly must set
  it to v1.70.0. Builds for netbsd/amd64, freebsd/386 and freebsd/arm still
  embed an older SQLite without the fix; the released binaries all have it.
- Stores now secure the file SQLite actually opens. These are rejected before
  anything is created: `file:` URIs with a `vfs` parameter, a repeated `mode`,
  a NUL byte, a host other than `localhost`, user information, a `#` fragment,
  or a query Go and SQLite would read differently. URI `mode=rw` and `mode=ro`
  require an existing database.
- An agent-memory store opened by `file:` URI used to keep its signing key in
  a decoy directory. It now fails to open with an error naming the old
  directory and the `mv` to run; go-llm does not move private keys itself. An
  in-memory agent-memory database needs an explicit `KeyDir` or injected
  credentials.

### Quality-sensitive routes may budget less context (#479)

`quality_ctx_ceiling` is now populated, from the embedded catalog (Qwen3.5 and
Qwen3.6 at 262,144) and from a new per-model `models.json` field that wins
over it. `chat`, `reasoning`, `code-review`, `planning` and `analysis` use the
smaller budget when a ceiling applies, which can change model selection,
sticky routing and fallback order. Two roles on the same provider/model with
different nonzero ceilings, or a negative ceiling, now fail `Load`.
`configview` gains an optional `quality_ctx_ceiling` field and
`config.SetRoleModelResult` gains `DroppedQualityCtxCeiling`.

### Library API changes from the sandbox and secret work (#576, #424)

- `golem.CommandPermissions` gained `Limits []string` and is no longer
  comparable with `==`.
- `golem.New` validates every session's sandbox policy, the host included: a
  host runtime with any network, memory, CPU or capability constraint fails
  with an error wrapping `agenttools.ErrSandboxPolicy`.
- `agenttools.VerifyCommand.Run` returns a `VerifyResult` alongside every
  error, including a zero result for a refusal before launch. Check the error
  before the exit code.
- Existing `agenttools` Seatbelt callers: the backend now refuses to construct
  or spawn while a descriptor above stdio lacks close-on-exec (as Bubblewrap
  already did), so `agenttools.ValidateSandbox` and `golem.New` fail with an
  error wrapping `ErrSandboxPolicy`; mark your descriptors close-on-exec
  first. Execution is limited to the reviewed system roots, the workspace,
  private temp and the exact approved executable.
- A native `golem.Options.Sandbox` requires `ProfileTrusted` and admits only
  library-built tools bound to the session's root and policy
  (`agenttools.CheckSandboxBindings`).
- A dispatched child blocked by `Secrets`, `configured_secrets` or a
  content denial now reports the fixed `Partial result unavailable: blocked:
  sensitive content` instead of falling back to its last message, with no
  setting.
- When an `agent.SensitiveTextInterceptor` blocks, every finding in that hook
  keeps only bounded metadata (interceptor, rule, verdict, numeric fields).
  Free-text `Detail` from every interceptor and the observer is dropped
  before risk, telemetry and errors are built, and hook and observer errors
  become `agent.ErrDiagnosticsSuppressed`. Observers that read `Detail` on
  such a block see none.

## Protections that are opt-in

A default Golem session (no `-interceptors`, no `-sandbox`) and a default
`go-llm-mcp` (no `GO_LLM_MCP_TOKEN`) get none of the following. In release
terms: exact configured-secret protection is available, opt-in through
`-interceptors`, and default sessions are not covered; MCP HTTP authentication
is optional, and TLS without a token stays unauthenticated.

| Protection | How to turn it on | What a default session does not get | Limits when on |
| --- | --- | --- | --- |
| Exact configured-secret protection (#424) | `golem -interceptors`; library hosts build the guard with `interceptor.NewConfiguredSecrets` from `cfg.SecretMatcher()`, install it on the orchestrator and `agenttools.NewDispatch`, and add `openaicompat.WithContentGuard` to each non-loopback client built with `provider.GuardHTTPClient` (the matcher alone gives no origin binding or redirect refusal) themselves | No check of tool arguments or outbound request bodies for credentials resolved from `models.json` | Values of at least 8 bytes, exact case-sensitive substrings. JSON escapes are decoded; split values and base64, percent or other encodings are not. Loopback providers, native Ollama clients (remote ones included), the MCP server, the `golem` library's automatic bootstrap, `golem index`/`source`, `llm-bench` and independently built providers are not covered. Headers, URLs and responses are not inspected. The set is fixed at startup. |
| Injection detectors and `Secrets` (#517) | `golem -interceptors` | Pattern detection of instructions and secret-shaped values; the always-on guards still run | Unchanged: #517 recorded the decision to keep them opt-in (`docs/security/interceptor-defaults-decision.md`). |
| MCP HTTP authentication (#428) | `GO_LLM_MCP_TOKEN` for `go-llm-mcp -transport http`; `mcp.WithHTTPBearerToken` for library callers | Loopback h2c and TLS on any permitted bind stay unauthenticated. An existing TLS remote deployment is open to every caller that can reach it until a token is set. | One shared token, no identity. `GODEBUG=http2debug=2` logs the `Authorization` header before the gate. Golem's own MCP client cannot send the header (see Known issues). |
| Native command sandbox (#576, #708) | `golem -sandbox seatbelt` (macOS) or `-sandbox bwrap` (Linux), with `-sandbox-network denied` (default) or `allowed` | A default Trusted session runs its commands, scratch execution and post-write verification on the host with your filesystem and network authority (Inspect runs no commands) | A native session mounts no retrieval, auto-index or model memory tools, and `-rag-db`, `-agent-memory`, `-delegate`, `-dispatch`, `-mcp-stdio`, `-mcp-http`, `-progressive` and `-grounding` are usage errors with it. Does not confine `/consult`, git-context helpers, MCP servers or the external editor. Neither CLI backend sets a memory/CPU quota. Seatbelt leaves launchd reachable and cannot load toolchains outside its reviewed roots; Bubblewrap's `ip-denied` leaves pathname Unix sockets in the workspace reachable. Sandboxed commands can write `.git` metadata (see Known issues). No native backend on Windows. |

### Evidence behind the native sandbox claims

The two backends are tested on every PR by required checks:
`Linux Sandbox (bwrap)` (`GO_LLM_REQUIRE_BWRAP=1`) and `macOS Compile Smoke`
(`GO_LLM_REQUIRE_SEATBELT=1`), which also run the non-race `Golem native
wiring` steps. #708's Seatbelt exec-confinement cases carry recorded
red/restored mutations in its PR (#713). The published containment inventory
(`docs/security/containment-inventory.md`) does not yet count all of this, and
v0.6.0 makes no inventory claim beyond it:

- `ENV-BWRAP` (the bwrap payload sees only the approved environment) is
  `unobserved(bwrap)`: its test runs in CI, but no mutation has been recorded
  for it on a Linux host.
- There is no `EXEC-SEATBELT` row yet; #708's exec tests and mutations are not
  in the inventory or its mutation ledger.
- #576's `TestNativeWiring*` tests are not registered on the `bwrap` and
  `seatbelt` inventory profiles.
- The `windows` profile has no mandatory rows. `GRANT-MCP` (M1) and
  `GRANT-SUBMITPLAN` (P1) are expected to pass there but have not been
  observed green.

[#699](https://github.com/kstruzzieri/go-llm/issues/699) tracks all four. It
is not part of v0.6.0. `PATH-ABS` and `PATH-DOTDOT` (W1, W2) are also
unobserved on Windows; they stay gated on `capability:unix` outside #699.

## Other consumer-visible changes

- With `-interceptors`, the startup notice lists the new guard first
  (`interceptors: enabled (configured_secrets, zero_width, ...)`), and the
  guards-only line now ends `(always on; -interceptors adds detectors,
  secrets, configured secrets, canary)`. Scripts that match these lines need
  updating.
- A run refused for sensitive content, including an outbound content denial,
  fails with `run blocked: sensitive content detected`, keeps the goal out of
  CLI history and does not write the content-full trace. A resumed session
  whose stored history already holds a configured key is refused on every
  turn to a remote provider under `-interceptors`; start it with `-fresh`.
- New public API: `config.Config.SecretMatcher`,
  `interceptor.NewConfiguredSecrets`, `agent.SensitiveTextInterceptor`,
  `agent.BlockedError.Sensitive`, `interceptor.SensitiveBlocked`,
  `provider.ErrContentDenied`, `openaicompat.WithContentGuard`,
  `mcp.WithHTTPBearerToken` and `mcp.ErrInvalidHTTPBearerToken`. A content
  denial is not an infrastructure error: no fallback, retry or breaker change.
- On APFS, point reads no longer list every ancestor directory; one read costs
  about a tenth of a millisecond regardless of directory size (#558).
- Scratch snapshots resolve `..` in symlink targets the way the host does
  (#660).
- `mcpclient` closes the connection when the MCP SDK's `Connect` fails, so a
  server with an unsupported protocol version no longer leaks its process or
  session (#406).
- Concurrent first opens of one agent-memory record store no longer report a
  false signing-initialization failure (#631). This resolves a v0.5.0 known
  issue.
- `golem ops` reads each backend in parallel with its own 5 s budget (#662).
- `llm-bench`: an injection-resistance corpus and report (#452), interceptor
  arms, census and Secrets evidence reports (#517), a single-attempt capture
  mode `-replay-attempt` (#687), and serialized judge-cache migrations (#593).
- `docs/security/containment.md` and `containment-inventory.md` publish what
  Golem's shipped boundaries contain and what they do not; the pre-push and CI
  security gate runs the containment scenarios (#452).

temporary modfile replacing go-llm in a scratch copy of Firn; consumer

executing them.

Firn's `golem.New` sites (`internal/ai/runtime.go` and
`internal/git/generator.go`) set no `Tools`, `Profile`, `ToolAllowlist` or
`Sandbox`, so they run as Inspect with no `ErrProfileIncompatible`. Setting
`Profile: golem.ProfileInspect` explicitly is recommended for clarity. Firn
does not use `CommandPermissions` or `VerifyCommand`. Its own
`openaicompat.NewClient` clients and the `golem` library bootstrap install no
content guard, so Firn gets no exact configured-secret checks unless it adds
them. The selected modules move to modernc.org/sqlite v1.46.2 and
modernc.org/libc v1.70.0.

## Known issues

- **Sandboxed commands can write `.git` metadata**
  ([#721](https://github.com/kstruzzieri/go-llm/issues/721)). Both native
  backends grant writes to the whole workspace, `.git/hooks`, `.git/config`
  and `.git/info` included. A sandboxed command, or a post-write verifier
  running model-written tests, can plant a hook or config that the host runs
  later, unsandboxed, at the next `git commit` or checkout. Scratch commands
  are not affected. Until #721 lands, review `.git/hooks` and `.git/config`
  after a native session that ran untrusted code.
- **launchd is reachable from Seatbelt commands**
  ([#712](https://github.com/kstruzzieri/go-llm/issues/712)). Whether a
  broker can start work outside the profile is unverified.
- **Seatbelt cannot load toolchains outside its reviewed roots**
  ([#722](https://github.com/kstruzzieri/go-llm/issues/722)). Homebrew and
  GOROOT toolchains and the `/usr/bin/git` and `/usr/bin/python3` xcrun shims
  fail under `-sandbox seatbelt`. Use a host Trusted session, or keep the
  toolchain and caches inside the workspace; never widen the policy.
- **Golem cannot authenticate to a token-protected `go-llm-mcp`.** Golem's MCP
  client cannot send an `Authorization` header, so `-mcp-http` against a
  server with `GO_LLM_MCP_TOKEN` gets 401. Use `-mcp-stdio`, or leave the
  token unset on loopback. No open issue tracks the client header yet (the
  #428 documentation named #578, which shipped in v0.5.0 without it).
- **Exact configured-secret checks, residuals** (#424, accepted at merge): a
  chat request is denied after slot admission (only embeddings are denied
  before it); in a fallback chain where an unguarded primary failed before a
  guarded fallback was denied, the run is under-charged by one reservation;
  step responses published before a denial are not rewritten; and the
  `secret_findings` telemetry counts only `secrets` blocks.
- **MCP HTTP server** (#428 follow-ups, pre-existing): the HTTP server sets no
  `ReadHeaderTimeout`, and nothing at startup says whether bearer
  authentication is on.
- **Grants and workspace changes**
  ([#420](https://github.com/kstruzzieri/go-llm/issues/420), not new in
  v0.6.0). Write grants cover the whole workspace. Exec and verifier grants do
  not notice a changed script, executable or data file, so an edit followed by
  a granted run is not re-approved (containment scenarios X3, X4, B1, V1, D1
  and D2 are declared `uncontained`). Command output can print
  credential-path files that `read_file` refuses.
- Local stdio MCP servers keep host-user filesystem and network authority, and
  `-sandbox` does not apply to them
  ([#580](https://github.com/kstruzzieri/go-llm/issues/580)).
- The Seatbelt inherited-descriptor repair can mark a reused descriptor
  close-on-exec under a narrow race; it never makes a descriptor inheritable
  ([#711](https://github.com/kstruzzieri/go-llm/issues/711)). Bubblewrap's
  bind sources are pathnames, and its descriptor audit is not atomic with the
  spawn ([#484](https://github.com/kstruzzieri/go-llm/issues/484)).
- A same-plan `-review-manifest` round, which #643 still allows over
  execution history, can silently replace the workflow route
  ([#679](https://github.com/kstruzzieri/go-llm/issues/679)).
- The containment inventory gaps listed under "Evidence behind the native
  sandbox claims" ([#699](https://github.com/kstruzzieri/go-llm/issues/699)).

## Release scope

The [v0.6.0 milestone](https://github.com/kstruzzieri/go-llm/milestone/3)
has six closed issues and no open issues at the release stamp: #387, #424,
#428, #452, #517 and #576. The milestone also lists PR #666, which shipped in
v0.5.0 with #665. The release also carries closed issues outside the
milestone (#406, #479, #558, #593, #631, #632, #642, #643, #648, #651, #652,
#660, #662, #687, #688, #689 and #708), AgentFlow 1.1 and 1.2 support from
[PR #705](https://github.com/kstruzzieri/go-llm/pull/705) and
[PR #730](https://github.com/kstruzzieri/go-llm/pull/730), which have no
issue, CI and test-only fixes (#306, #630, #653, #693), and the #424 and #428
test pins from [PR #729](https://github.com/kstruzzieri/go-llm/pull/729).
#730 merged after the stamp and was folded into this release afterwards.
Provenance and
approval continuity (#581 to #584), quarantined ingestion (#434), retrieval
tagging (#435) and scoped retrieval for dispatch children (#554) moved to the
[v0.7.0 milestone](https://github.com/kstruzzieri/go-llm/milestone/4) at the
2026-10-27 freeze, which also placed #469 and the second `golem ops` PR
(#654) there directly. The
[least-privilege roadmap](../least-privilege.md#dependency-order-and-release-scope)
adds no scope to this release.
