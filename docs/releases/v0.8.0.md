# Upgrading to go-llm v0.8.0

Read this before upgrading from v0.7.0. For older dependencies, apply the
[v0.7.0 upgrade guide](v0.7.0.md) first; it links the earlier notes in turn.
The v0.8.0 section of the [changelog](../../CHANGELOG.md) contains the full
entries.

v0.8.0 closes six security gaps, adds opt-in strict approval, and makes
capability answers come from a shared evidence log. A working-directory `models.json` can no longer send your
environment secrets to a URL it names, command output no longer carries
credential files, writes to agent harness files and the files they load always
ask, and the native sandboxes no longer let a command reach launchd or plant
git hooks and config.

Most of these are on by default, so most upgrades change what a session does
without a code change. Check six things: upgrade AgentFlow to 1.3, pass
`-config` for a working-directory `models.json` that uses `${NAME}` keys,
expect commands that name `.env` or other credential files to be refused,
expect `/auto-edits` and `-p -allow-tool write_file` to stop covering harness
files, expect some `git` commands to fail inside a native sandbox, and drop
any call to `agentflow.Client.ProbeRecovery`, which is removed.

Three more change what Golem sends or reports. Answers saved by v0.7.0's
capability probes stop counting, so a model's tool support is checked again on
first use: at most two requests per invocation, which may load a model under
llama-swap. A run the provider refuses with a 4xx other than 401, 403 or 429
fails with `provider_rejected` instead of `internal`. A turn that ends without
an answer starts its footer with `no answer ·` instead of `done ·`.

## Changed defaults and new requirements

### Golem requires AgentFlow 1.3 (#766, #765)

Golem now requires AgentFlow 1.3.0 or a later 1.x. AgentFlow 1.2 and older are
refused before any other AgentFlow call, with
`agentflow 1.2 is too old; need >= 1.3`. This includes fresh `-goal` and
`-plan` runs, which still ran on 1.2.1 in v0.7.0. Upgrade AgentFlow before or
with Golem.

- On 1.2.x an edit left by a stopped amendment did not fail the run:
  `-agentflow-resume` could reach `state: complete` with `proof: verified`
  while the edit stayed unverified. AgentFlow 1.3.0 fails `verify-run` and
  `finish-run` on it (kstruzzieri/agentflow#103).
- The separate 1.2.1 recovery refusal from v0.7.0 (#756) is gone. A script that
  matches `agentflow 1.2.1 cannot drive recovery` must match the too-old text
  instead. `-agentflow-status` now runs `agentflow --version` once.
- When AgentFlow 1.3 allows `amend` but marks it `automatic: false`,
  `-agentflow-status` and `-agentflow-resume` say an operator must decide and
  name the steps: run the advised `amend-step`, record the edit in the new
  attempt, then resume. `-agentflow-resume` now settles an amendment an operator
  opened and recorded an edit in.
- `-agentflow-status` used to prefix every projection check failure with
  `resume: blocked by unsafe or malformed projection:`. The line now reads
  `resume: blocked:`. Exit codes and JSON output are unchanged; a script that
  matches the old text must change.
- Library callers: `agentflow.Client.ProbeRecovery` is removed, and the
  `-review-manifest` run no longer calls it. Use `CheckVersion` or `Probe`,
  which refuse the same versions.

### A working-directory `models.json` can no longer spend your environment secrets (#776)

A `models.json` found only because it sits in the current directory could name
any environment variable in `api_key` (`"${AWS_SECRET_ACCESS_KEY}"`) and a
`base_url` of its choosing, and go-llm would send that secret there.

- A config found by working-directory discovery now refuses every `${NAME}`
  `api_key` reference, and any malformed one, with the error code
  `key_reference_refused`, before any environment variable is read.
- To use that file's references, name it: `golem -config ./models.json`,
  `go-llm-mcp -config ./models.json`, or `GO_LLM_CONFIG=./models.json` for one
  run. Do not export a relative `GO_LLM_CONFIG`: it would trust the
  `models.json` in every directory you run from. Saving the config to another
  path or as a profile lifts the refusal; saving it back to its own path keeps
  it.
- Literal keys, the user config (also when you run from inside its directory),
  `GO_LLM_CONFIG` and explicit paths are unchanged.
- `llm-bench` now fails on the refusal (`set GO_LLM_CONFIG or pass
  -judge-model`) instead of silently falling back to its built-in judge.
- An `openai-compat` provider with an `api_key` never runs the loopback
  discovery scan (ports 8080-8090); only its configured URL is probed. When that
  URL does not serve the model, Golem prints
  `openai-compat backend discovery skipped: provider "<key>" has an api_key;
  pass -base-url to use another port`. Keyless providers still find a moved
  local backend.
- Consumers that mirror `config`'s closed error-code list must add
  `key_reference_refused`. Firn must add it before it bumps go-llm
  (kstruzzieri/firn-ide#524).

### Command output no longer carries credential files (#777, #789)

`read_file` already refused credential paths, but a command could print the
same files. The screen is on in every session and every library host that uses
`agent/tools` exec, with no switch.

- **Refused commands.** A command that names a credential file is refused before
  it is planned or approved, with `tool call blocked by interceptor invariants
  (credential_path)`. That covers an argv word such as `.env`,
  `--env-file=.env`, `HEAD~2:.env`, `@.env` or `-f.env`, the same text in an
  inline `sh -c` script, and a command that names the file only to leave it out
  (`grep -r --exclude=.env x .`, `find . -name .env`). A git exclusion pathspec
  such as `':(exclude,glob)**/.env'` as its own argv word is allowed. A `dir` at
  or below `.git`, `.ssh`, `.gnupg`, `.aws` or `.kube` is refused
  (`protected_dir`).
- **Withheld output.** Every value of 8 bytes or more from a `.env`-style file is
  withheld from command output, ordinary ones included: with
  `NODE_ENV=development` in `.env`, `development` is replaced by
  `[withheld: credential-path content (credential_path)]` wherever a command
  prints it. The same applies to each line of 8 bytes or more of a credential
  file, URL userinfo and `extraheader` values in `.git/config`, and the
  userinfo of a `.git-credentials` line. Patch output stops at the first
  credential-file section, and a line over 32 KiB now ends that stream's output
  with a marker.
- **Large workspaces.** Before each spawn the screen walks the workspace and
  reads its credential files within a time budget of 5 seconds, added to the
  tool's timeout. When it cannot finish (a file over 256 KiB, a directory this
  process cannot read, the budget exhausted), the command still runs, and its
  result shows the exit code and a note naming the cause, with no output. On one
  Apple-silicon Mac a tree of 355,611 entries in about 36,000 directories takes
  1.7 to 2.1 s; a directory-heavy tree of 1,000,000 entries takes 10.2 s and
  withholds every command's output at the default. `-credential-screen-budget`
  (`5s` to `5m`) raises the budget; library hosts use
  `ExecToolsOptions.CredentialScreenBudget` or
  `(*Workspace).SetCredentialScreenBudget`. On platforms other than Linux and
  macOS, exec output is always withheld.
- The `run_command` and `start_command` descriptions gain one sentence about
  these refusals. A consumer that pins prompts or hashes tool specifications
  sees the change. `llm-bench` keeps its corpora's original descriptions, so
  registered trace hashes are unchanged.

### Writes to harness files, and to the files they load, always ask (#725, #784)

`write_file` and `edit_file` calls that target an agent instruction or harness
configuration file now always need a person. `/auto-edits` and the `a` answer
no longer cover them, and `golem -p -allow-tool write_file` (or `edit_file`)
and AgentFlow `-approve-plan-edits` deny them.

- The set has 28 entries, including `AGENTS.md`, `CLAUDE.md`, `.mcp.json`,
  `.golem.json`, `models.json`, the `.claude`, `.cursor`, `.codex` and `.agent`
  folders, GitHub Copilot's instruction and hook paths, and `.vscode/mcp.json`
  and `.vscode/settings.json`. `models.json` and `.vscode/settings.json` were
  ordinary writes before, so expect prompts where there were none.
  `submit_plan` under `-approve-plan-lock` still writes `.agent/` itself.
- Under `/auto-edits`, a write also asks for any file a harness file loads, runs
  or links to: Markdown `@` imports (followed five hops), scripts and arguments
  in hook and MCP commands in the configuration files Golem reads, OpenCode
  `instructions`, and symlink targets at harness paths. Fixed paths in folders
  above the workspace count, so a hook in `~/.claude/settings.json` that runs
  `"$CLAUDE_PROJECT_DIR"/scripts/lint.sh` makes `scripts/lint.sh` ask. No answer
  creates a grant.
- AgentFlow parallel promotion refuses a whole batch, writes and deletions, if
  any path in it is covered (`refuse parallel promotion: <path>: <reason>`).
- Golem fails closed. When it cannot finish the search (an unreadable or
  malformed harness file, `~/.claude/settings.json` included, or a bound
  crossed), every file write asks. The preview's first line then reads
  `harness reference: <reason>`; `-p` prints `golem: harness reference: ...`
  after its denial line.
- Library hosts: `agent/tools` plans these writes with an empty approval key,
  and `agent/interceptor` exports `IsHarnessPath` and `HarnessPaths`. A host
  that uses a plain `agent.Approver` never receives the key.

The full list is in [docs/golem.md](../golem.md#files-a-harness-file-loads-runs-or-links-to).

### Native sandboxes refuse writes to git metadata (#721)

A command run under Seatbelt or Bubblewrap could write the workspace's git hooks
and config, which git later runs outside the sandbox on your next commit or
checkout. Both native sandboxes now refuse to change, rename, replace or delete
the workspace's git metadata: hooks, anything under `info`, `config`,
`config.worktree`, `commondir`, `gitdir`, the `.git` entry itself and the
`.git` file of a submodule or linked worktree. This covers nested repositories
and the git directories under `.git/modules` and `.git/worktrees`, for
verification commands as well as commands. Seatbelt also refuses creating any of
this during the run, in any letter case.

- Ordinary git work in an existing repository keeps working. On Linux the
  tests run add, commit, checkout, stash, gc and rebase, in the top-level
  repository, a submodule, a nested repository and a linked worktree. On macOS,
  git itself does not start under the Seatbelt profile (Homebrew git and
  `/usr/bin/git` both fail at startup), so the writes git makes in normal use
  were checked under the new rules alone.
- Some git commands now fail inside the sandbox on purpose. On both backends:
  `git config` (including setting `core.hooksPath`), `git sparse-checkout`,
  `git worktree add` and `git submodule update --init`. `git remote add`,
  `git remote set-url` and setting an upstream branch fail under Seatbelt and
  are expected to fail under Bubblewrap, where git can report the upstream
  failure yet still exit 0. Under Seatbelt, `git worktree remove`,
  `git worktree prune`, and `git init` or `git clone` into the workspace without
  `--bare` fail too.
- An error reading the workspace's git layout before a spawn, other than a
  missing entry, refuses the command.
- The approval preview's sandbox line adds `git_metadata=ro` (Seatbelt) or
  `git_metadata=ro(existing)` (Bubblewrap). The approval key does not move, so
  existing grants stay valid.

What this does not cover is under [Known issues](#known-issues).

### Seatbelt commands can no longer reach launchd (#712)

A Seatbelt command inherited a connection to launchd, through which it could
`kickstart` a loaded job outside the sandbox, `enable` or `disable` jobs
persistently, and `print` your launchd domain, environment variables included.
Seatbelt commands now start through a native launcher with no launchd
connection and no exception ports, with descriptors close-on-exec by default.
The sandbox profile itself is unchanged.

Embedders: the Seatbelt backend empties the host process's legacy registered
Mach port table before each spawn, under Go's `syscall.ForkLock`. A fork from C
code in the host that does not take that lock is not serialized against a
Seatbelt spawn, and can hand that command the host's launchd connection.

### The conversation store migrates to schema v6 (#582, #583)

Every `agent` run now keeps a record of whether content from outside the
conversation has entered it, reported as `Result.Exposure`. Golem stores it on
the conversation row, bound to the row's revision, and carries it across turns,
resume and compaction. The record is always kept, whether or not strict
approval is on, and by itself changes nothing: no call is gated on it unless
strict approval is on.

- The session database moves to schema version 6 (two nullable columns) on
  first open. An older binary reads and writes the file as before; a row it
  writes reads back as having no record.
- Conversations saved before v0.8.0, or last written by an older binary, read
  as unknown provenance until a new or cleared conversation replaces them. That
  matters only under strict approval (below).
- A custom `SessionStore` that does not carry `conversation.Conversation`'s new
  `Exposure` field reads as unknown too. See
  [Exposure record](../library.md#exposure-record) for what a store and a
  conversation-writing host must carry.
- `Runtime.ThreadExposure` reads the record the next turn on a thread would
  start from. It never writes a row, and on a runtime with no `SessionStore` it
  opens the default session database on first use, creating and migrating it
  if absent, as `CompactThread` does.
- A run started inside another run's tool shares that run's record. A child run
  started on a fresh `context.Background()` instead of the tool's context
  escapes the record, as it does for budgets.

### The capability store migrates, and Ollama answers re-key on digest (#734, #735, #736)

These apply from this release whether or not the evidence log is attached:

- Golem opens one shared capability store,
  `$XDG_DATA_HOME/golem/fingerprints.db` (else
  `~/.local/share/golem/fingerprints.db`), and hosts can open the same store
  with `fingerprint.OpenSharedStore`. A new directory is created 0700, the file and
  its sidecars are 0600, and a path inside the workspace is refused. If the file
  cannot be used the store falls back to memory for that run and Golem prints a
  warning.
- The first open by this release migrates an existing store in place. An older
  binary that opens the migrated file skips the migrations it does not know, and
  the `capability_probes` table is untouched.
- Capability answers and fingerprint profiles for Ollama models now key on the
  model's real digest (a name with no tag takes its `:latest` form's digest), so
  existing rows are re-checked once on next use. When probing is enabled,
  fingerprint profiles re-run once per Ollama model, latency benchmark included.
- Capability names from Ollama's `/api/show` are matched case-insensitively, and
  `tool_call` is accepted beside `tools`: a model listing `Tools` or
  `tool_call` now reads yes.
- Recommendations break an exact tie on provider name, then model name, so tied
  models list in a fixed order.
- The OpenAI-compatible shim (`compat`) now passes an upstream finish reason
  through, so a reply cut off at `length` reports `length` even when it carries
  a tool call. A reply with tool calls whose upstream reason is `stop` still
  reports `tool_calls`.
- `Provider` implementers: return a non-nil slice for an empty model listing. A
  nil slice reads as `malformed_response` when a listing is published.

These apply to Golem, which attaches the evidence log from this release (next
section), and to a library registry given `provider.WithEvidenceLog`. A library
registry without the log routes, lists and explains as before:

- Tool-call answers are read from and written to the evidence log only. On an
  OpenAI-compatible server a check is one streamed chat request offering a
  single no-argument tool, with `max_tokens` 2048. Automatic checks share an
  allowance of two generation requests per registry; a check the allowance
  cannot fund returns `provider.ErrAutomaticProbeBudgetExhausted` and is never
  read as a no. On Ollama the check stays a read of `/api/show`.
- Routing, `ProjectListedModels`, `ExplainToolCall` and
  `configview.ExplainCapabilities` rank evidence the same way: an explicit
  `capabilities` list, then a check or use, then what the provider reports, then
  the catalog, then the model type. A checked no now beats a catalog or type
  yes, and a provider's missing `tools` beats a catalog yes.
- FIM routing follows the decided `insert` capability instead of the Ollama
  template: an explicit list without `insert` refuses FIM with
  `the model's decided capabilities exclude insert`, and one with `insert`
  admits it.

### Golem routes on the capability evidence log, and explicit checks delete nothing (#737)

Golem now reads and writes capability answers in the shared store's evidence
log, the log `configview.ExplainCapabilities` reads.

- **Old answers stop counting.** Answers in the old `capability_probes` table
  no longer count, so each model's tool support is checked again on first use.
  A checked no beats a catalog or type yes. An older Golem keeps working on the
  same file and does not see the new answers.
- **Automatic checks.** They share an allowance of two requests per Golem
  invocation, startup included, which buys one model's tools check. Each check
  prints its progress on stderr (model, endpoint host, method, requests
  reserved, output tokens requested), never on stdout, in a `-p` record or in
  the headless stream. An exhausted allowance leaves the model unknown, never a
  no, and the next invocation has a fresh one.
- **Inconclusive checks.** A chain whose first entry comes back inconclusive can
  fail startup on that run and move on at the next, because a matching
  inconclusive attempt suppresses automatic checks of that model for 24 hours.
  A check that sent a request and then failed with a 5xx, its own timeout, or a
  broken or oversized reply suppresses them for 5 minutes instead
  (`check_failed`). A 4xx, a cancelled check or one that sent nothing records
  nothing. The startup message for an inconclusive entry names
  `golem models -probe-all`, and a refused check (allowance used up, store
  unreadable, or a provider with no evidence binding) is reported as an error
  with its reason, not as a missing capability.
- `-no-cap-probe` turns automatic checks off and, as before, makes routing
  ignore stored checks; the store still opens for a derived input ceiling.
- **`golem models -probe-all` and `-reprobe` delete nothing.** For each provider
  of the agent chain they first print on stderr what they will check (each
  model, its method, usual and maximum requests, output tokens requested,
  request timeout, response byte limit, and whether it may load the model),
  then check exactly that and print each result there. `-reprobe` re-checks
  fresh answers too. If stderr cannot take a provider's whole plan, the command
  exits before sending that provider a check. stdout keeps one line per entry. A provider with more than
  25 distinct models is refused (`batch_too_large`). Ctrl-C stops a check in
  flight and says so.
- An Ollama model is checked with one `/api/show` and filed under its content
  digest. Once it has a yes or no for each checked capability, it is not read
  again until `-reprobe` or a new model version; an inconclusive answer is
  checked again by the next `-probe-all`.
- **What a check costs.** A tools check requests up to 2,048 output tokens per
  request and sends at most two requests. Those are requests, not a billing
  guarantee: a server may ignore the token limit. Golem bounds local time and
  response bytes; billing is the provider's. A local openai-compat check may
  load a model under llama-swap. A check is not proof that a full tool call
  round-trips.
- **Output.** `golem models -json` reports a checked no, and Ollama's live no
  (a capability list without tools), as no rather than unknown, so the
  candidate is ineligible. `golem models` prints `tool_call=MISSING (runtime)`
  instead of `(unknown)` for Ollama's live no. A reply that completes with an
  unusable tool call reads tool_call `tool_call_invalid`.
- A model whose provider reports no tool support no longer lowers Golem's input
  ceiling.
- A name-only yes (a hosted model has no digest) goes stale after 30 days and
  still counts; using the model does not refresh it
  ([#741](https://github.com/kstruzzieri/go-llm/issues/741)).
- Consumers that render capability details need words for `tool_call_invalid`
  and `check_failed` (kstruzzieri/firn-ide#496). Consumers that mirror
  `configio.ErrorCode` must add the check codes listed under
  [Library additions](#library-additions-and-api-changes).

### A provider's refusal of a run fails with `provider_rejected` (#740)

A run whose model request the provider refused used to fail with `internal`,
the code a bug in Golem gets.

- When the provider's final reply to the run's model request, after any
  fallback, is an HTTP 4xx other than 401, 403 and 429, `run.failed` carries
  `provider_rejected`, and so does the `golem.result.v1` record that
  `golem -p -output-format json` and `stream-json` write. A host that matched
  `internal` for these failures sees the new code. 429 stays
  `provider_unavailable`, 401 and 403 stay `internal`, and every code that
  applied before (for example `policy_blocked` or `invalid_request`) still
  wins.
- Only the error the run's model caller returned counts. With Golem's own model
  callers, a 4xx met while listing models or probing capabilities during
  routing is reported as before.
- The message is unchanged and no field is added to the payload.
- Library hosts: `agent.Result.ModelError` is new and runtime-only (never
  serialized). It holds the error the model caller returned for the request
  that ended the run, and is nil when one of the run's own stream callbacks
  failed or an output block was joined with it. Inspect it with `errors.As`;
  do not use it as the target of `errors.Is`, because a model caller may
  return a value that cannot be compared.

### Golem recovers a final answer left only in the reasoning (#767)

Some reasoning models end a turn with the answer inside their reasoning and an
empty reply, so Golem finished with no answer and a one-shot run exited 1.

- Golem now asks once more. When a turn's final step has no tool calls, a blank
  reply and non-blank reasoning, and a step is left, it spends one more
  tool-free step asking for the final answer only. Reasoning never becomes the
  answer. This is on for REPL goals, `-p` runs and hosts that use the Golem
  runtime: the `-trace` request carries `recover_thinking_only_answer: true`,
  and the `-telemetry` run span counts the extra step. AgentFlow planner runs
  and task steps, and dispatch children, do not ask.
- When the follow-up also has no answer, the turn ends as before: `-p` exits 1,
  text format prints `one-shot: model produced no final answer`, and `json` and
  `stream-json` report `status: error` with `empty_answer`.
- The stderr footer of a REPL or `-p` turn that ends without an answer now
  starts `no answer ·` instead of `done ·`, whatever stopped it. The rest of the
  footer is unchanged. Scripts that match `done ·` must change.
- Library hosts opt in with `agent.Request.RecoverThinkingOnlyAnswer`. Each
  recovery step records a `final_answer_retry` event in `Result.Events`. The
  placeholder assistant turn and the request for the answer go on that step's
  request only, never into the run's messages or saved history. Reasoning a
  model caller only streams, without returning it in the response, is not
  recovered.

### Library hosts that want strict approval need `agent.FreshApprover` (#584)

`agent.Request.StrictApproval` and `golem.Options.StrictApproval` are new and
off by default; nothing changes for a host that leaves them off. Once a strict
run is exposed, an approver that does not implement `agent.FreshApprover` is
denied rather than asked, so add `ApproveFresh` before opting in.

- While approvals are suspended (`agent.ApprovalsSuspended(ctx)`), a tool that
  declares it needs no approval is asked about too, except plain reads and the
  tools named in `agent.Request.StrictExempt`. `golem.Runtime` names
  `delegate_code` and `dispatch` there.
- A host's `FreshApprover` is therefore asked about `agent_memory_create` and
  `agent_memory_promote` in an exposed strict run, with an empty preview, and
  should render the call's arguments. The Trusted approval floor still exempts
  all four of those library tools; only strict approval asks about the memory
  writes.
- Narrowing follows each command tool's own backend: a natively sandboxed
  command tool that allows network narrows in any exposed strict run, including
  one named in `StrictExempt`. `golem.New` checks that it can build the
  network-denied policy only when `StrictApproval` is set and its own `Sandbox`
  is native and allows network.

### Library additions and API changes

Additive unless marked. An unkeyed literal of a struct that gained a field stops
compiling: `conversation.Conversation`, `agent.Request`, `agent.Result`,
`provider.ChatResponse`, `provider.ToolCallExplanation`, `golem.Options` and
`agent/tools`' `ExecToolsOptions`.

- **Removed:** `agentflow.Client.ProbeRecovery` (#766).
- **No longer comparable:** `fingerprint.SQLiteStore` (#734) now holds the
  store's account secret as a byte slice, so code that compares two
  `SQLiteStore` values with `==` or uses one as a map key stops compiling.
  `*SQLiteStore`, the pointer `fingerprint.NewStore` returns, is unaffected.
- **Changed signature:** `configio.RefreshInventory` takes variadic
  `RefreshOption`s; calls compile unchanged, but a function value of the old
  type does not.
- `agent` (#582, #584): `Exposure`, `Result.Exposure`, `Request.PriorExposure`,
  `Request.StrictApproval`, `Request.StrictExempt`, `FreshApprover`,
  `ApprovalsSuspended`; `Request.RecoverThinkingOnlyAnswer` and the
  `final_answer_retry` event kind (#767); `Result.ModelError`, runtime-only
  (#740).
- `conversation` (#583): `Exposure`, `Conversation.Exposure`.
- `golem`: `Options.StrictApproval`, `Runtime.ThreadExposure`.
- `agent/interceptor`: `IsHarnessPath`, `HarnessPaths` (#725), `IsGitConfigPath`
  and the `CredentialArgv` check kind (#777).
- `agent/tools` (#777, #789): `ExecToolsOptions.CredentialScreenBudget`,
  `(*Workspace).SetCredentialScreenBudget`, `MinCredentialScreenBudget`,
  `MaxCredentialScreenBudget`.
- `config`: `CodeKeyReferenceRefused` (#776), `ModelCapabilityPolicy` and
  `(*Config).CapabilityPolicy` (#736).
- `fingerprint` (#734, #735, #736): `OpenSharedStore` and the shared store's
  evidence log, `CapabilityProber`, `CapabilityProbeRequest`,
  `CapabilityProbeResult`, `ProbeAnswer`, `RecipeForRequest`, and the `Detail*`
  constants, among them `DetailCheckFailed` (#737, a sixth inconclusive code)
  with its lifetime `CapProbeCheckFailedTTL`; and `AnswerRows` (#737).
  `fingerprint/probers`: `(*OpenAICompatProber).ProbeCapabilities`.
- `provider` (#735, #736): `ChatResponse.FinishReason`, `WithEvidenceLog`,
  `CanonicalEndpoint`, `WithCapabilityProbeProgress`,
  `ErrAutomaticProbeBudgetExhausted`, `ErrEvidenceUnbound`,
  `ErrEvidenceUnreadable`, `ExplainEvidence`, `LoadCatalog`, and
  `ToolCallExplanation.Unsaved` and `.EvidenceUnreadable`; `EndpointHost`
  (#737).
- `configio` (#734, #737): `WithPublish`; `PlanCheck`, `RunCheck`,
  `CheckOptions` (with `RuntimeDigests`), `RunOptions`, `CheckPlan`,
  `CheckItem`, `CheckResult` and `CheckAnswer`; and 14 check codes on
  `ErrorCode`: `auth_failed`, `model_refused`, `refused`, `rate_limited`,
  `timeout`, `unreachable`, `server_error`, `rejected`, `malformed_response`,
  `destination_not_granted`, `plan_stale`, `listing_required`,
  `batch_too_large` and `response_too_large`. A plan is sealed to its key and
  endpoint and holds 25 models at most; `RunCheck` sends exactly that plan
  through its own guarded client and refuses a changed key or endpoint
  (`plan_stale`) or an ungranted remote endpoint (`destination_not_granted`)
  before sending anything. A 403 or 404 is `model_refused`, remembered for 7
  days, only when another model gave a completed reply in the same run;
  otherwise it is `refused` and not saved. An executable plan stays in the
  process that made it.
- `configview` (#736): `ExplainCapabilities`, `ExplainListing` and their result
  types.

The changelog lists every new name.

## Protections that are opt-in

A default Golem session (no `-strict-approval`) keeps the exposure record but
never reads it: grants and `/auto-edits` approve as in v0.7.0, whatever has
entered the conversation.

| Protection | How to turn it on | What it does | What it does not do |
| --- | --- | --- | --- |
| Strict approval (#584) | `golem -strict-approval`; library hosts set `golem.Options.StrictApproval` or `agent.Request.StrictApproval` | Once outside content enters a conversation (an MCP tool result, `/consult` advice a run accepts, a library tool that declares no origin, or history with no record), grants and `/auto-edits` are suspended. Each file write or edit, command, background start, verifier run and agent-memory write (`agent_memory_create`, `agent_memory_promote`) then asks `[y/N]` every time, and a run with no one to ask is denied. On the host runtime, the prompt for a command, background start or verifier says `network is not confined`. | Workspace files and command output, `curl` included, never expose a conversation. `delegate_code` and `dispatch` stay unprompted. Exposed content still reaches the configured model provider, hosted or local. Only `/new`, a successful `/clear` or `-fresh` starts clean; a plain start reopens the workspace's conversation, so history saved before v0.8.0 keeps asking there until you run `/clear`. Accepted with `-p` and the AgentFlow modes, where it has no effect today. |
| Network narrowing under strict approval (#584) | `-strict-approval` with `-sandbox seatbelt` or `-sandbox bwrap` and `-sandbox-network allowed` | Once the conversation is exposed, a command, background start or verifier run approved in it runs on a copy of the sandbox policy with network denied (`network=denied` on Seatbelt, `network=ip-denied` on Bubblewrap). Startup refuses to start when the host cannot run that copy. | A live CLI MCP session runs on the host and is never narrowed. A command approved while the conversation was clean runs as approved, and a job already running keeps its network. On Bubblewrap, pathname Unix sockets inside the workspace stay reachable. |

Strict approval is opt-in approval continuity. It is not prompt-injection
protection: it asks a person again once outside content is in the conversation,
and it does not detect or remove injected instructions. The
[decision record](../security/strict-mode-decision.md) states this and the
limits of its reach.

With strict approval on, startup's `permissions:` line shows
`strict-approval=on (exposed by MCP results, accepted /consult advice or unrecorded history)`,
and `/grants` shows the conversation's state, a clean one as
`exposure: clean (files and command output are not tracked)`.

The decision record measured what strict approval costs, over synthetic content:

- In a clean conversation it added no prompts, in the scripted evaluation and in
  a local-model pass over seven workflows.
- Once a conversation was exposed, every consequential call asked once, with no
  duplicates, and each task still completed. In the local-model pass a person
  answered 56-67% of consequential calls with strict approval off and all of
  them with it on.
- On Seatbelt, the native-sandbox leg showed an exposed conversation's command
  lose IP network under `-sandbox-network allowed`. The `Linux Sandbox (bwrap)`
  CI job runs the same leg under Bubblewrap and fails if it skips.
- The network-narrowing containment rows are mutation-verified on both
  backends: STRICT-8 on Seatbelt (M-418) and STRICT-9 on Bubblewrap (M-419,
  #821), in [containment-mutations.md](../security/containment-mutations.md).

The rest of the [v0.6.0 table](v0.6.0.md#protections-that-are-opt-in) still
describes what a default session does not get: the native command sandbox,
exact configured-secret protection, the `-interceptors` detectors and MCP HTTP
authentication all stay opt-in. Two of the native sandbox's limits listed there
are closed in this release: Seatbelt no longer leaves launchd reachable (#712),
and sandboxed commands can no longer write existing `.git` metadata (#721).
Two Bubblewrap rows that had never been mutation-tested are now verified in a
Linux container with Bubblewrap: the payload environment (ENV-BWRAP, M-420) and the
credential screen on command output (CMP-EXEC-CREDENTIAL-OUTPUT-BWRAP, M-180),
PR #825. No row of the containment inventory is left `unobserved`.

These are on by default, not opt-in: the working-directory key refusal (#776),
the credential screen on command output (#777), the harness-file prompts (#725,
#784) and the exposure record (#582, #583). The git-metadata and launchd
refusals apply to every native-sandbox session.

## Other consumer-visible changes

- `-agentflow-resume` tells a retried attempt which files a stopped attempt left
  behind, in a `Retry context` section, and says how to keep each one (#774). If
  that read fails, the model does not run and the attempt is blocked as a failed
  run is.
- When a retried attempt still leaves an in-scope file unrecorded, the error
  names the files and the two ways out instead of
  `reached state "file_receipts_missing" before gates` (#774). Scripts that
  match the old text must change.
- The destination consent screen adds `sends api_key from $NAME` or
  `sends a literal api_key` under each destination whose provider sends a key
  (#776).
- The openai-compat client replaces its own key with `[redacted]` in error text
  built from a server response, including malformed status lines and headers
  (#776).
- Golem trace files carry each step's `finish_reason`, which the openai-compat
  provider sets (#735).
- openai-compat assembles a streamed tool call in linear time: one 1 MiB call in
  10,000 fragments took 13 seconds and now takes 7 milliseconds (#807). There
  is still no limit on how large a streamed tool call may be.
- [docs/least-privilege.md](../least-privilege.md) is rewritten to describe the
  shipped behavior, including that strict approval does not limit what reaches
  the model (#581).

## Known issues

New in this release, strict approval:

- **Command output does not expose a conversation**
  ([#819](https://github.com/kstruzzieri/go-llm/issues/819)). A `curl` that
  fetches a page holding injected instructions leaves the conversation clean,
  so grants keep working on the turns that follow. This is the largest
  documented gap in strict approval's reach; #819 proposes exposing the
  conversation for native-sandbox commands with network allowed.
- **A detector hit in a workspace file does not expose a conversation**
  ([#820](https://github.com/kstruzzieri/go-llm/issues/820)). The
  `-interceptors` detectors tag or block the one result; a poisoned workspace
  file never suspends approvals.
- Recalled agent-memory records, and files an exposed conversation wrote, read
  as workspace content to a later clean conversation. Writing either one in the
  exposed conversation needed a yes.

New in this release, capability evidence. These apply to Golem and to library
hosts that attach the evidence log:

- **A 4xx on the first chain entry's automatic check** (401, 403, 404 or 429)
  leaves later entries unchecked on every run, because a failure that belongs
  to one key records no attempt. Fix the key or model name, or run
  `golem models -probe-all` ([#828](https://github.com/kstruzzieri/go-llm/issues/828)).
- **While the capability store cannot be read after it opened**, every model
  lookup asks the provider again, and no Golem output says the store could not
  be read. A check whose save failed is kept in memory for the registry's life,
  but a failed read discards kept answers with the rest; if both failures
  happen together, a catalog yes stays in force until the store reads again
  (#828).
- **Startup** (#828). Ctrl-C during startup ends Golem without a `cancelled`
  line; no further check request is sent and nothing is half-saved. Startup
  preflight can accept a model that has a tool answer but lacks chat or stream,
  which routing then rejects. If another process records a 24-hour
  inconclusive attempt while a check is in flight and that check then fails
  with a server error, automatic checks of the model can resume after 5 minutes
  instead of 24 hours (at most one extra check).
- **`golem models -probe-all` and `-reprobe`**
  ([#829](https://github.com/kstruzzieri/go-llm/issues/829)) exit 0 when every
  provider's plan is refused. A gateway that answers 404 to the tools request
  for a model that exists (OpenRouter, for one) has that model kept as
  `model_refused` for 7 days when another model in the same run completed.
  `refused` prints with no hint about what to do.
- **Ollama digests.** A re-pulled Ollama model reads under its old digest until
  the next listing. A library host that checks an Ollama model without a
  runtime digest or a current stored listing, against a server that names no
  digest, files a name-only answer Golem's routing does not read.
- **FIM refusal text.** A model with no `insert` evidence at all is refused with
  `the model's decided capabilities exclude insert`, which reads like a checked
  no. FIM also differs both ways between the log and no-log paths: an explicit
  list with `insert` beside a template without `.Suffix` is refused without the
  log and admitted with it.
- **Explanations.** `ExplainToolCall` labels an unsaved check's yes beside a
  catalog yes as `catalog`, and still lists the provider's models unless an
  explicit capability list answers.
- **Offline explanations can differ from routing.** `configview.ExplainCapabilities`
  and `ExplainListing` see what Ollama reports about a model only after a
  refresh publishes it (`configio.RefreshInventory` with `WithPublish`), ignore
  the model family Ollama reports, and return `provider.ErrEvidenceUnreadable`
  when the store cannot be read, while routing keeps serving an answer it has
  already cached.
- **`mcp.WithFingerprintStore` hosts stay on the legacy path.** A library host
  that builds an MCP server with it keeps the `capability_probes` table and the
  non-streaming probe. The `go-llm-mcp` binary does not set it.
- Per-capability assertions, and checks for `insert` and `vision`, are not yet
  available.

New in this release, final-answer recovery (#767):

- **The recovery step can reach another model**
  ([#832](https://github.com/kstruzzieri/go-llm/issues/832)). It advertises no
  tools, so routing that chooses by required capabilities can send it to a
  different model in a preferred chain than the one that reasoned. The
  recovery step never sends the reasoning, so whichever model answers works
  from the conversation alone, and a different model may not reach the same
  conclusion.

Residual limits of this release's security fixes. The changelog lists each in
full:

- **Git metadata (#721).** A sandboxed command can create a directory git treats
  as a bare repository, whose config host git can run
  ([#803](https://github.com/kstruzzieri/go-llm/issues/803)); run
  `git config --global safe.bareRepository explicit` (git 2.38 or later) to
  close it on your machine. Bubblewrap protects only the metadata that exists
  when a command starts, so a new `commondir`, `config.worktree`, `hooks` or
  `info` can be created there
  ([#802](https://github.com/kstruzzieri/go-llm/issues/802)). Not covered on
  either backend: hooks kept in the working tree through `core.hooksPath`,
  symbolic and hard links among the metadata, a git directory made with
  `--separate-git-dir`, and other files the host runs later, such as a
  `Makefile`, `package.json` scripts or `.envrc`.
- **launchd (#712).** A launchd job you set up to watch a path inside the
  workspace can still be triggered by a sandboxed write, and with network
  allowed a command can connect to Unix-domain sockets the profile lets it
  resolve.
- **Harness files (#725, #784).** Writes made by commands are not covered, nor is
  a workspace rooted in a submodule or nested repository inside a harness
  folder. What a hook command does at run time is best effort: variables other
  than the project-folder ones, command substitution and scripts that call
  scripts are not followed.
- **Credential screen (#777).** Encoded or transformed output, values under 8
  bytes or spanning a line break, committed content printed without its path,
  credential files outside the workspace, and AgentFlow and MCP output are not
  covered. `docs/golem.md` lists the rest.

Pre-existing:

- **Routed step records do not decode in Go**
  ([#831](https://github.com/kstruzzieri/go-llm/issues/831)).
  `provider.AttemptStatus` writes its name as a string but cannot read it back,
  so Go code that decodes a serialized `agent.Result` holding route outcomes,
  or a Golem `-trace` file, fails. Readers in other languages are unaffected.
- **Concurrent runs can evict each other's pending plans**
  ([#822](https://github.com/kstruzzieri/go-llm/issues/822)). Each tool instance
  keeps one pending plan. When two runs plan the same tool with different
  arguments, the first fails with `exec preview missing; retry` or the write
  tools' equivalent. Since #584 a plan approved in the other approval state is
  refused, so the collision is safe, but the failure is spurious.

Unchanged from [v0.7.0](v0.7.0.md#known-issues), none fixed here: Abacus
streamed usage, fence keys (#745), compaction (#748), `cache_affinity` in config
panels (#749) and usage figures (#751).

Fixed here: a one-shot run that exited 1 when the answer was only in the
reasoning, seen on v0.6.0 and v0.7.0 (#767, above). v0.7.0's
capability-evidence item is fixed in part:
Golem's answers now key on the endpoint, not the provider name, so two configs
that name different endpoints `local` no longer share them. A hosted yes still
counts after it goes stale at 30 days (#741).

The v0.7.0 AgentFlow recovery item (#756) no longer applies: v0.8.0 refuses
every 1.2 build, and AgentFlow 1.3.0 fails `verify-run` and `finish-run` on an
edit a stopped attempt left (#766).

Unchanged from [v0.6.0](v0.6.0.md#known-issues), none fixed here:

- Seatbelt cannot load toolchains outside its reviewed roots
  ([#722](https://github.com/kstruzzieri/go-llm/issues/722)).
- Golem cannot authenticate to a token-protected `go-llm-mcp`, and the #424 and
  #428 residuals stand.
- Grants do not notice workspace changes
  ([#420](https://github.com/kstruzzieri/go-llm/issues/420)).
- Local stdio MCP servers keep host-user authority
  ([#580](https://github.com/kstruzzieri/go-llm/issues/580)).
- Seatbelt and Bubblewrap descriptor races
  ([#711](https://github.com/kstruzzieri/go-llm/issues/711),
  [#484](https://github.com/kstruzzieri/go-llm/issues/484)), the workflow route a
  `-review-manifest` round can replace
  ([#679](https://github.com/kstruzzieri/go-llm/issues/679)), and the containment
  inventory gaps ([#699](https://github.com/kstruzzieri/go-llm/issues/699)).
