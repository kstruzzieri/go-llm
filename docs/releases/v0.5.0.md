# Upgrading to go-llm v0.5.0

Read this before upgrading from v0.4.0. For older dependencies, apply the
[v0.4.0 upgrade guide](v0.4.0.md) first; it links the v0.3.0 notes in turn.
The v0.5.0 section of the [changelog](../../CHANGELOG.md) contains the full
entries.

v0.5.0 narrows what Golem and its children inherit by default: MCP servers,
AgentFlow gates and Golem's own `git` calls get environments built from
scratch, deterministic tool guards are always on in the CLI, and workspace
reads re-check the path they were allowed. Most upgrade work is operator-side
(re-approving MCP pins, installing AgentFlow 1.x, naming required variables).
Library breaks are concentrated in `mcpclient`, `compat` and the `route://`
resources.

## Breaking changes

### MCP pins bind the connection; stdio servers start clean (#578)

Pins now store keyed fingerprints of the stdio launch (resolved program and
symlink target, arguments, working directory, environment policy) or the exact
HTTP endpoint, and a changed connection is refused before anything is launched
or contacted.

- Every server pinned by v0.4.0 or earlier reports `connection_missing` until
  you run `golem mcp inspect` and `golem mcp approve -digest … -connection …`
  once, with the same `-root`, server and `-mcp-env` arguments as startup.
  `approve` now requires `-connection`.
- Stdio servers start in `-root` with only `PATH`, `HOME`, `LANG`, `USER` and
  `TMPDIR` (plus the Windows baseline), and a relative program path containing
  a separator (`./bin/server`) resolves against `-root`, not Golem's current
  directory. Name anything else with
  `-mcp-env 'alias=NAME,...'`; an unset named variable blocks that server
  (`env_unset`). Relative and empty `PATH` entries are dropped.
- HTTP servers are pinned to one exact endpoint, every redirect is refused,
  and endpoints with userinfo, fragments, dot segments, backslashes, IPv6 zone
  IDs or non-ASCII hosts fail as `invalid_config`.
- The first run creates `<user data dir>/golem/mcp-pins/connection-hmac.pem`.
  An unreadable, insecure or corrupt key makes the pin store unavailable.
- Downgrading: a v0.4 binary reports pins written by v0.5.0 as
  `pin_unavailable`.

Library callers: `mcpclient.Approve` takes `ApprovalDigests{Catalog,
Connection}` and requires both. Build stdio environments with
`Server.WithEnv(InheritEnv(...), SetEnv(...))` and set the working directory
with `Server.WithDir`. `Manager.Close` returns the fixed text
`mcpclient: closing MCP sessions failed`; match causes with `errors.Is` and
`errors.As`. See [external MCP catalog trust](../golem.md#external-mcp-catalog-trust).

### AgentFlow 1.x only; gates start clean (#612, #577, #624)

- `-goal`, `-plan`, `-agentflow-resume` and `-agentflow-status` run
  `agentflow --version` first and refuse anything outside 1.x before any
  mutation.
- Plans whose `schema_version` major is not 1 (including Golem's previous
  `0.3.0` plans) are refused. Workspaces whose `.agent/` lock, contract or
  ledger rows are not 1.x are refused, naming the file. Finish or
  `build-proof` the run with AgentFlow 0.x, move `.agent/` aside, and re-plan;
  see [upgrading from AgentFlow 0.x](../llm/agentflow-task-mode.md#upgrading-from-agentflow-0x).
- AgentFlow, its gates and its `git` calls receive a baseline environment plus
  names approved with the repeatable `-agentflow-env NAME` flag (on `golem`
  and `golem audit`). Gates that relied on inherited `GOFLAGS`, `GOPRIVATE`,
  `HTTPS_PROXY`, `SSL_CERT_FILE` or provider keys need explicit approval. An
  approved name that is unset fails the launch. `PWD` is now the gate's own
  directory and is runner-owned (#624).

Library callers: `agentflow.PreflightP0` rejects non-1.x plans,
`agentflow.Compile` emits `1.0.0`, and `agentflow.NewSrcExecRunner` requires an
absolute checkout containing `src/agentflow/__init__.py`. Approve parent
variables with `(*agentflow.ExecRunner).AllowEnv`; an unset approved name
fails with `agentflow.EnvNotSetError`. New exports: `Client.CheckVersion`,
`VersionError`, `PlanSchemaVersion` and `SupportedSchemaVersion`. See
[AgentFlow subprocess environment](../golem.md#agentflow-subprocess-environment).

### Deterministic tool guards are always on in Golem (#575, #622)

Argument invariants, exec-class egress labels and scoped-child refusal
reporting are installed on every Golem run, including `-p` and dispatch
children, with no opt-out. Matching calls (writes under `.git`, `.ssh`,
`.gnupg`, `.aws` or `.kube`; credential-file reads; inline
fetch-into-shell pipelines) are refused before approval, and grants cannot
override them. Three consecutive refusals stop the run; a `-p` run stopped
this way exits 1. Every session prints a `guards:` line on stderr. #622 widens
the inline-shell recognizer to common option forms such as `bash -e -c` and
`sh -xc`. These are tripwires, not confinement. Library consumers remain
opt-in. See [interceptors](../golem.md#interceptors-and-secret-detection).

### compat browser, Host and status boundaries (#633, #636, #637)

- `compat.New` sends no CORS headers by default. Browser clients pass their
  exact origin to `WithCORS`; `ListenAndServe` returns
  `compat.ErrInvalidCORSOrigin` for an origin no browser sends.
- Cross-origin browser POSTs are refused with 403 `cross_origin_not_allowed`,
  and any request whose `Host` is not loopback, the `WithAddr` host, or a name
  added with `compat.WithAllowedHosts` is refused with 403
  `host_not_allowed`. List `host.docker.internal`, LAN names and wildcard-bound
  `WithTLS` hosts explicitly. Non-browser clients are unaffected by the
  origin check.
- `GET /v1/status` replaces `providers[].error` with `error_class`, and
  `compat.ProviderStatus.Error` is replaced by `ErrorClass`.

### `route://` resources emit stable JSON (#634)

`route://breakers`, `route://warmth` and `route://sticky` keep their URIs and
top-level shapes but now emit flat snake_case entries with RFC 3339 UTC times.
The nested `info`, `Key` and `Info` objects are gone, breaker state is a
string, and error text is replaced by `last_error_class`. Readers must move to
the new keys listed in the changelog.

### Workspace reads verify the path they were allowed (#613)

On Linux and Darwin, reads behind `read_file`, `search`, `glob`, `list`,
scoped dispatch, `write_file`/`edit_file` previews and the exported undo and
hash readers re-resolve the guarded path from the workspace root after opening
and fail closed if it no longer reaches the same object. Expect
`path changed during access` from the read tools, the existing
`file identity changed between stat and open` from the exported helpers, and
`ErrRootReplaced` when the root or a scoped child's scope moves. Build a new
`Workspace` after a top-level root replacement. This reverses #448's rule that
a pinned directory keeps serving reads after it moves.

This is decision integrity, not adversary resistance: a process that can
rename can still place content at an allowed name, hard links make a name
unreliable provenance, the re-resolution is a sequence of lookups rather than
an atomic snapshot, bytes are read after it, and case-only or
normalization-only renames on case-insensitive filesystems are not detected.
Other platforms are unchanged. See the
[workspace read boundary](../least-privilege.md#workspace-read-boundary-613).

### Credential files and protected dispatch scopes (#627)

`search` skips `.env` files (except templates), `.netrc`, `_netrc`, `.npmrc`,
`.pypirc`, `.git-credentials`, a `config` file under `.git`, and anything under `.ssh`,
`.gnupg`, `.aws` or `.kube`, for every consumer of `agent/tools`. A `dispatch`
task scoped at or below `.git`, `.ssh`, `.gnupg`, `.aws` or `.kube` is
refused. The matching `read_file` refusal stays opt-in for library consumers
(install `interceptor.Invariants`). Custom `PathDeny` patterns now match
normalized paths: write them in normalized form. This is a tripwire, not
confinement: `glob` and `list` still show these names, and shell commands,
`retrieve`, MCP tools, verifier commands and copies or hard links under other
names can still reach the bytes.

### SQLite open rules (#619)

Stores fail to open when the WAL switch reports any journal mode other than
`wal`, including `file:` URIs with `immutable=1` or `nolock=1`. For read-only
access, use `rag.OpenSQLiteStoreReadOnly` (which now also accepts `file:` URIs
and rejects `_pragma` options) or pass your own handle to
`provider.NewSQLiteFeedbackStore`. On Windows, file-backed stores now open,
and UNC and device paths are rejected.

### Golem's own `git` calls start clean (#623)

Worker-worktree and git-context `git` processes receive a fixed baseline plus
Golem's settings. SSH agent, proxy and certificate variables, `GIT_ASKPASS`,
`GIT_CONFIG_COUNT`/`GIT_CONFIG_PARAMETERS` injection and other parent
variables no longer reach hooks, filters or helpers. Move such settings into
global git configuration, run without `-plan-workers`, or pass
`-no-git-context`. See [Golem's own git calls](../golem.md#golems-own-git-calls).

### Off-host `localhost` is a destination denial (#654)

A `localhost` base URL that resolves to a non-loopback address now matches
`provider.ErrDestinationDenied`. `golem.New`'s config-driven bootstrap, Golem
and `go-llm-mcp` fail at startup instead of starting without that provider's
model list; headless Golem reports `provider_unavailable`.

## Other consumer-visible changes

- On Linux and Darwin, a scratch command checks its snapshot's root, cwd and
  (when inside the workspace) executable against the approved objects, and
  the Seatbelt and Bubblewrap backends check that the executable they resolve
  is the approved object; both refuse with a "retry" message on a change
  (#553). The checks bind the object, not its bytes, so an in-place rewrite is
  not detected. Seatbelt now launches self-contained executables reached through symlinks
  outside its read roots (Homebrew style); tools that load libraries from
  outside those roots are still stopped by the dynamic loader. See the
  [exec launch boundary](../least-privilege.md#exec-launch-boundary-553).
- `-mcp-tools 'alias=name,...'` and `mcpclient.Server.WithTools` expose only
  the named tools of an attached server; the full catalog is still pinned
  (#579).
- AgentFlow task steps whose agent run stopped early (step limit, repeated
  tool errors, budget) are recorded as `blocked` before any gate and exit 1
  (#611). `-agentflow-status` reports them as `step_unclaimed`, and
  `-agentflow-resume` reruns them in a new attempt. Edits from the stopped run
  stay in place. Either restore or delete them before resuming, or the new
  attempt must write every in-scope file that is still changed (writing the
  same bytes again is enough). Only if it leaves one untouched does resume
  fail closed with `file_receipts_missing`, leaving the new attempt open; then
  block that attempt with `agentflow block-step` before restoring files, or a
  later resume settles it on its gates without running the model. See
  [stopped step runs](../llm/agentflow-task-mode.md#stopped-step-runs).
- `golem ops` adds a read-only backend console (table, `-json`, `-watch`) for
  llama-swap v235 and Ollama on loopback (#654).
- Undo refuses while the workspace root is unreachable instead of reporting
  success (#658). New read-only `Workspace.VerifyRoot`.
- The destination guard closes request bodies on every denial (#655).
- Transcript audit-column upgrades (#590), feedback weight-reader schema
  validation (#591) and routing-feedback lock waits (#592) behave correctly
  under concurrent opens and deadlines.
- MCP admission keeps the refusal reason and first-pin notice when the
  session close is canceled (#620).
- `golem` subcommands no longer echo command-line text in argument errors
  (#577).

## Consumer compatibility checked for this stamp

Targeted compile checks used Go 1.27.1 and release source `c3335002`, with a
temporary modfile replacing go-llm in a scratch copy of Firn; consumer
checkouts were unchanged. Each check was repeated against `v0.4.0` so that
failures could be attributed. These checks compile packages and tests without
executing them.

| Consumer checkout | Result |
| --- | --- |
| Firn IDE `288732a7` (develop) | Pins go-llm v0.3.0 with `go 1.25.0`, so it still needs the v0.4.0 migration: the release source rejects `MemorySessionStore.Save`, which returns only `error` (#542). With a scratch-only `Save` signature shim, `go build ./...` passes on both `v0.4.0` and the release source, including the root Wails application (with an empty `frontend/dist`). Test compilation in `internal/ai` reports the same 21 errors on both, all from `Save` call sites and fakes; every other package's tests compile. v0.5.0 adds no compile break for Firn. |
| Flux ML `cd6529235673` | No go-llm requirement in the available checkout; no active integration to compile. |
| Quantum Trader `a16673908180` | No go-llm requirement in the available `backend/go` module; no active integration to compile. |

Firn's develop branch already enforces CAS in `MemorySessionStore` (it returns
`conversation.ConflictError` on a revision mismatch); what remains is returning
the committed revision, moving its `go` directive to at least 1.27.0, and
updating its tests and fakes. Firn does not import `mcpclient`, `compat` or
`agentflow`. Behavior it may notice through `golem` and `agent/tools`: the
#613 read checks, the #627 `search` skip, and the #654 startup failure.

## Known issues

- A fresh `golem -plan` over a workspace whose only step has an open attempt
  with a failed gate exits 0 and prints a proof pack recording incomplete steps
  (#651). This predates v0.5.0. Related: a fresh `-plan` relocks over an
  existing `.agent/` tree (#643), non-stop step-run errors leave the attempt
  open (#642), and resume cannot recover from a failed gate (#652).
- A concurrent first `memory.OpenRecordStore` can report a false
  signing-initialization failure (#631).
- Local stdio MCP servers keep host-user filesystem and network authority
  (#580).

has 15 closed issues and no open issues at the release stamp: #553, #575,
#577, #578, #579, #590, #591, #592, #611, #612, #613, #619, #623, #624 and
#627. The release also carries closed issues outside the milestone (#622,

[PR #620](https://github.com/kstruzzieri/go-llm/pull/620), and the terminal

for its later phases. The stretch items (#387, #424, #428,
#517, #554 and #576) moved to the
[v0.6.0 milestone](https://github.com/kstruzzieri/go-llm/milestone/3). The
[least-privilege roadmap](../least-privilege.md#dependency-order-and-release-scope)
adds no scope to this release.
